## 3. 根因（决定性证据：同夜两次委派，两种结果）

两次委派**同 stage（`media_generate`）、同注入面、同模型**，仅相隔 1 小时 20 分：

| | 20:11 那次（`conv-1791115916-c8b9ece1`） | 21:29 那次（`conv-1791120591-7151a0bf` + `conv-1791120785-320fb409`） |
|---|---|---|
| 父委派 `current_step` | 「为尚未建运镜轨迹图的 10 个分镜撰写**运镜轨迹图**提示词草案」 | 「为 11 个 shot 各撰写一张**分镜表格图**提示词草案」 |
| 子代理推理中「四大要素」 | **2 次**（明确引用：`时长标注：模板四大要素之一"景别与时长标注"`） | **0 次**（整会话 grep = 0） |
| 是否先读已确认范本 | **是** —— 先 `read_draft` 读 S8 已确认卡 `draft-1790779722-7bd22e2d`（该卡每格带「约3s」）作格式基准 | **否** —— 只读状态与规格，未读任何已确认范本 |
| 产出卡标签 | `运镜轨迹图·S1`–`S11` | `分镜表格图·S1`–`S11` |
| **每格时长** | **10/10 张全部带**（`约4s`/`约3s`/`约2.5s`…） | **0/11 张带**（`约Ns` 正则 0 命中） |
| 时长来源 | 明确按 Skill `:151-164` 景别经验值逐镜估算并配平总时长 | 无 |

**⇒ 要求在场而未被执行的实证。** 21:29 那次的具体机制有二：

1. **误判注入面**（结构性误导）。平台下发时把两章正文**拼接后剥掉了章节标签**
   （`registry.section_for` 只回正文，`planner.py:551-558` 加一行「注入 Skill 章节」头即下发），
   而 `<media_generator>` 章里写着「具体提示词写法见下方「媒体提示词」章节」。
   子代理第一条推理原文：
   > "the injected chapter is 'media_generate' … The prompt writing method refers to the write_media_prompt chapter,
   > **which I'm not authorized to read (not injected)**."

   它以为只拿到一章、看不见章界，于是把注意力收拢到「照模板填槽位」——**模板之外的散文要求（四大要素）不再被当成硬要求**。
   这正是 D-28 描述的机制（「模型只填模板给出的位置，散文要求不落地」）。

2. **无范本可抄**。20:11 那次能带时长，很大程度是它 `read_draft` 抄了**已被用户确认**的 S8 卡
   （该卡每格带「约3s」）；21:29 那次没有这一步，只按模板骨架生成，模板没有的槽位就整块缺席。

**写入侧零拦截**：`prompt_gates.validate_prompt_write`（`src/video_agent/core/prompt_gates.py:179-229`）
自 2026-09-10 起**字数地板已退役**，对提示词内容只留一条「含对白且项目有音色参考」的软提醒 ⇒
漏时长**不会有任何拒收或回喂**，模型与用户都收不到信号。

## 4. 为什么「按 Skill 生成」得不到图1（重要张力）

图1（Flova 成品）里最显眼的几项，**在两侧 Skill 中都 0 命中**：

| 图1 特征 | 本仓 `SKILL.md` | Flova `skill-AI 短剧一站式生成.md` | 来源 |
|---|---|---|---|
| `pure black line art` / `technical drafting` | 0 | 0 | **Flova 模型自发**（Skill 模板反而写 `photorealistic`） |
| `LEGEND BOX` / `Panel N —` 骨架 | 0 | 0 | **Flova 模型自发**（Skill 模板是 `Row` 三段式） |
| 每格 `时长: 0-6s` | 只有散文要求（`:130`），模板无槽位 | 同 | 散文要求 + Flova 模型补齐 |
| `16:9 landscape` | 0（模板写 `3:4`） | 0（模板写 `3:4`） | **Flova 模型自发改了模板**（与本仓模型同向） |
| `no watermark, no subtitles` | 0（表格图模板独缺；同章三视图/四视图都有 `No text…`） | 同 | Flova 模型自发 |

⇒ **图1 是「同一份 Skill + Flova 模型的自发改写」的产物，不是「照 Skill 模板」的产物。**
用户「Flova 用同一份 Skill 也能产出带时长的表格图」的判断**成立**，但它成立的理由是
**Flova 模型把散文要求当硬约束并越出模板补齐**，而不是 Skill 模板里有时长位置。

因此想逼近图1，只有三条路（D-28 已列，均待裁决）：
1. 改 Skill 模板加时长槽位 —— **用户已否决**（「Skill 不能改」）；
2. 平台侧补要求 —— 属**复述章节内容**，正是 2026-09-30 批刚写严的禁区；且本轮证实**要求本已送达**，补复述只会加剧第二份事实源；
3. **让执行端遵守已有散文要求**（治「读到了不执行」），例如：下发时保留章节标签（消除 §3-1 的误判面）、或给「写表格图」这一步配一个已确认范本/客观自检。
