> **用户原问（第 5 条）**：
> 「skill 都写清楚了，字段为什么都对应不上，skill 里面的 `<storyboard_key_elements>`、
> `<storyboard_shots>`、`<storyboard_audio>` 就是对应的前端故事板的关键元素、分镜、音频。
> **skill 里面这些章节字段到底有没有对应在本项目中，要搞清楚。**」
>
> **船长声明**：此问题此前一直未被正面回答（各报告只零散提及个别章节）。

> 全部数字由 `.tmp_probe/section_mapping.py`、`section_inject.py` 实跑产出，可重放。

## 一、结论先行（一句话）

**10 个章节里：3 个真对应、4 个"半对应"、3 个根本够不着。**
用户点名的三个章节（`storyboard_key_elements` / `storyboard_shots` / `storyboard_audio`）
**确实对应**前端三个类目（keyElements / shots / audioItems）——
**但对应只到"类目"这一层，没到"字段"这一层**，这正是"字段对应不上"的由来。

## 四、用户点名的三章：确实对应到类目，但**没到字段**

用户的判断**基本正确**——三个章节确实对应三个类目：

| Skill 章节 | 前端类目 | 对应是否成立 | 证据 |
|---|---|---|---|
| `<storyboard_key_elements>` | **keyElements** | ✅ **成立** | `CAPABILITY_TOOL_STAGES['storyboard_key_elements'] = ('storyboard_ke',)`；该 section 抽取正常 |
| `<storyboard_shots>` | **shots** | ✅ **成立** | `… = ('storyboard_shot',)` |
| `<storyboard_audio>` | **audioItems** | ✅ **成立** | `… = ('storyboard_audio',)` |

**但"对应"只到类目这一层。** 平台**没有任何一张表**把章节与类目连起来（船长全仓检索：
「章节名 + 类目名」同现的文件 → **四个组合全部为「无」**）：
- 章节 → **section 名**（`storyboard_ke`）✅
- 章节 → **stage 名**（`storyboard_design`）✅
- section → **类目**（`keyElements`）❌ **缺**

**⇒ 所以"字段对应不上"的准确机制是**：
章节对应的是**内部 section 代号**，模型看不到这个代号；
模型能看到的是 `group_type` 三选一 + 草稿字段白名单（20 个字段，**无一个承载 Skill 语义**）。
**章节 → 字段这条链，中间断在"section 代号"上。**

## 五、⭐ 另外查到三个结构性缺口（此前各报告均未正面列过）

### 缺口一：**4 个章节永远无法注入执行者**

`PIPELINE_STAGE_KINDS`（可委派阶段）实测**只有 3 个**：
```
['script_analyze', 'storyboard_design', 'write_media_prompt']
```
而 `<image_generate>` / `<generate_video>` / `<audio_generate>` / `<video_assembler>`
对应的 stage（`image_generate` / `generate_video` / `audio_generate` / `video_assembler`）
**都不在其中**：

```
resolve_stage('image_generate')   = ''  → stage_tools=[]
resolve_stage('generate_video')   = ''  → stage_tools=[]
resolve_stage('audio_generate')   = ''  → stage_tools=[]
resolve_stage('video_assembler')  = ''  → stage_tools=[]
```

`resolve_stage` 对未知 stage **回落空串** ⇒ 这些章节**不可能被精准注入**。
（主代理仍可直调生成工具，但**它拿不到这四个章节的正文**。）

### 缺口二：两个集合不一致，且**无 lint 覆盖**

| 集合 | 规模 | 内容 |
|---|---|---|
| 能力面 `PIPELINE_CAPABILITY_TOOLS` | **7** | script_analyze / storyboard_key_elements / storyboard_shots / storyboard_audio / write_media_prompt / audio_generate / video_assembler |
| 委派面 `PIPELINE_STAGE_KINDS` | **3** | script_analyze / **storyboard_design** / write_media_prompt |

```
❌ 只在能力面、不在委派面: ['audio_generate', 'storyboard_audio',
                          'storyboard_key_elements', 'storyboard_shots', 'video_assembler']
ℹ️ 只在委派面: ['storyboard_design']
```

- `subagent.py:180-192` 的 fail-loud 校验**只覆盖 `PIPELINE_STAGE_KINDS` 内部一致性**
  （每阶段须有章节映射/标签/工具集）；
- **没有任何 lint 检查「能力面 ⊇ 委派面」**（`grep PIPELINE_STAGE_KINDS scripts/` → 
  只在 `acceptance.py:75` 注释与 `check_tool_descriptions.py:18` 提及，**无集合比对**）。

⇒ **这正是 2026-09-22 批6「三阶段合并」留下的未登记副作用**：
合并把 3 个原子阶段从委派面退役，但**能力面仍留着 5 个名字**，
两边从 8 处漂移至今**无人发现**。

### 缺口三：`<audio_generate>` 的承载根本不存在

flova 审计实测（船长采信其证据）：
- Skill 说音频由「系统音频生成通道」产出；
- 平台**无此通道**（`text_to_narration` / `text_to_instrumental` **0 命中**）；
- 前端"音频生成"按钮**实为 LLM 文本规划**（`generate-actions.ts:182`），不产音频文件。

⇒ 第 8 章**既不可注入、也无承载**，属**纸面章节**。

## 六、结论：用户的判断对在哪、我要补什么

### ✅ 用户对的

1. **三个章节确实对应三个类目**——用户说的没错；
2. **"字段对应不上"成立**——因为**章节只落到 section 代号，没落到模型可见的字段**；
3. **"没有按 skill 要求来"成立**——`<storyboard_key_elements>` 明写
   `key_element_audio` 归属，但模型**无字段可表达**（见 `05-用户反馈核查.md` §5）。

### ⚠️ 要补的（本文件新增）

1. **不是"某一个章节没接上"，而是三类系统性缺口**：
   - 4 个章节**够不着**（stage 不在委派面）；
   - 章节→类目→字段**三级链缺中间一级**；
   - 能力面与委派面**漂移且无 lint**。
2. **量化**：10 章节 → 真对应 **2** / 半对应 **6** / 够不着 **2**。

### ⇒ 对方案的补充（建议并入批 4/5）

| 补丁 | 内容 | 层 |
|---|---|---|
| **P-1** | 补「章节 → 类目」映射（唯一事实源），并把模型可见的 `group_type`/字段描述与之一致 | 说明层 + 字段层 |
| **P-2** | 补 lint：「能力面 ⊇ 委派面」集合比对（防再次漂移） | 门禁 |
| **P-3** | 决定 4 个够不着的章节怎么办：①补进委派面；②明确划归"主代理直调、不注入"并在文档登记 | 需用户裁决 |
| **P-4** | `<audio_generate>` 属纸面章节：要么补通道（大工程），要么在平台侧显式登记"承载缺失" | 需用户裁决 |
