# 补充卷 II：安全专项（最高严重度）

> 本卷记录审核中发现的**安全类缺陷**。所有条目均经**亲自复验**（读取源码行 + 纯逻辑验证 + 只读探测）。
> 与 `00-审核报告.md`（架构/工程质量）和 `01-补充取证与勘误.md`（机制空转）并列，本卷是**唯一涉及「可被外部利用」的缺陷**，优先级最高。

---

## 一、总判定

本项目在**架构安全模型**（闸机、同意章程、Context≠Consent、risk 分级、deny-by-default）上的设计水准**高于多数同类 Agent 产品**；但在**传统 Web 安全边界**（路径校验、鉴权覆盖面）上存在**基础性缺口**，且这些缺口与架构安全模型**完全无关**——架构层的闸机再严密，也拦不住一个直接读文件的路由参数。

**核心矛盾**：项目有 `state/repository.py` 那样**教科书级的路径校验**（`_PROJECT_ID_RE` 白名单 + `resolve()` 前缀双重校验，注释还写明「杜绝 ../ 等路径遍历字符」），却在 `web/routes/snapshots.py` 对**同一类输入**（URL 路径参数 → 文件路径）**零校验**。这不是「不知道怎么做」，而是**校验没有下沉为统一机制**——正是项目自己的 P2 原则（「能被代码机械校验的一律实现为代码校验」）在此处失守。

## 二、S-1【BLOCKER】任意文件读取 / 任意文件删除（路径遍历）

### 2.1 漏洞代码（复验）

```python
# src/video_agent/web/routes/snapshots.py:112-114
def _read_snapshot(project_id: str, snap_id: str) -> Dict[str, Any]:
    f = _snap_dir(project_id) / f"{snap_id}.json"      # ← snap_id 无任何校验
    if not f.exists():
        raise VideoAgentError("快照不存在", status_code=404, error_code=LEGACY_NOT_FOUND)
    try:
        return json.loads(f.read_text(encoding="utf-8"))   # ← 读任意文件

# src/video_agent/web/routes/snapshots.py:236-244
@router.delete("/conversations/snapshots/{snap_id}")
async def delete_snapshot(snap_id: str):
    """删除快照（不影响任何对话）。"""
    svc = StateManager.get_instance()
    d = _snap_dir(svc.active_project_id or "")
    f = d / f"{snap_id}.json"                          # ← 同一构造，无校验
    if not f.exists():
        raise VideoAgentError("快照不存在", status_code=404, error_code=LEGACY_NOT_FOUND)
    f.unlink()                                          # ← 删任意文件
```

触及点共 **3 处**（`snapshots.py:113` / `:197` / `:241`），**全部**使用 `d / f"{snap_id}.json"` 而未做任何校验。

### 2.2 利用原理（纯逻辑复验，未攻击真实服务）

Windows 下 `pathlib.Path` 的 `/` 运算符在右操作数为**绝对路径**时会**丢弃左侧前缀**：

```python
>>> from pathlib import Path
>>> d = Path('workspace/snapshots/proj')
>>> d / ('C:\\Users\\ASUS\\secret' + '.json')
WindowsPath('C:/Users/ASUS/secret.json')      # ← 前缀 workspace/snapshots/proj 被完全丢弃
```

（已实跑复验，输出如上。）

而路由参数 `{snap_id}` 接受**任意 URL 编码字符串**；Windows 驱动器号 `:` 与盘符可经 `%3A%5C`（`: \`）注入。因此：
- `GET /api/conversations/snapshots/C%3A%5CUsers%5C...%5Csomefile` → **读取宿主任意 `*.json`**；
- `DELETE /api/conversations/snapshots/C%3A%5CUsers%5C...%5Csomefile` → **删除宿主任意 `*.json`**。

**残留 `.json` 后缀约束**是真限制（`f"{snap_id}.json"` 强制追加），但 `data/api_providers.json`（含各供应商配置）、`data/runtime_settings.json`、`workspace/**/*.json` 均命中；且这些是**运行时关键配置**。

### 2.3 同仓对照：正确做法就在同一个仓库里

```python
# src/video_agent/state/repository.py:25-49 —— 同一类输入，双重校验
_PROJECT_ID_RE = re.compile(r"^[A-Za-z0-9][A-Za-z0-9_-]{0,63}$")

    def _project_dir(self, project_id: str) -> Path:
        """校验 project_id 并返回项目目录（白名单正则 + resolve 前缀双重校验）。

        非法 id（如 ../../etc）直接抛 StateError，防止路径遍历读写 workspace 外文件。
        """
        if not project_id or not _PROJECT_ID_RE.match(project_id):
            raise StateError(f"非法的项目 ID: {project_id!r}", error_code="INVALID_PROJECT_ID")
        pdir = (self._projects_dir / project_id).resolve()
        if not str(pdir).startswith(str(self._projects_dir.resolve()) + os.sep) \
                and pdir != self._projects_dir.resolve():
            raise StateError(f"非法的项目路径: {project_id!r}", error_code="INVALID_PROJECT_ID")
        return pdir
```

**结论**：`repository.py` 有白名单正则 **+** `resolve()` 前缀校验**双重**防护；`snapshots.py` **零**防护。同一仓库、同一类风险、两种标准。

### 2.4 加剧因素：鉴权默认关闭

```python
# src/video_agent/web/app.py:216-234
@app.middleware("http")
async def api_key_auth(request: Request, call_next):
    # 开发模式跳过认证
    if settings.environment == "development":
        return await call_next(request)          # ← 开发模式全放行
    ...
    key = request.headers.get("X-API-Key", "")
    if not settings.api_key or key != settings.api_key:
        return JSONResponse(status_code=401, ...)
```

```python
# src/video_agent/web/app.py:162-164 —— 开发模式 CORS 全开
_DEFAULT_CORS = "*" if settings.environment == "development" else "http://127.0.0.1:8080,..."
```

即：**开发模式下（项目默认运行模式），认证被完全跳过、CORS 为 `*`**。此时路径遍历漏洞可被**任何能访问该端口的进程或网页**利用（CORS 全开意味着恶意网页可发起跨域请求）。

**重要限定**（避免夸大）：生产模式（`ENVIRONMENT=production`）下 `api_key_auth` 生效，且「未配置 api_key 时拒绝所有请求」是 fail-closed 的安全默认。因此该漏洞的**现实暴露面**取决于部署配置。但即便如此，**认证不应是路径校验的替代品**——纵深防御要求两者独立成立。

### 2.5 目标设计（正向，非补丁）

**不做「在 snapshots.py 里加一个正则」的补丁**，而是把路径安全**下沉为统一机制**（对齐项目 P2）：

```
core/path_safety.py          # 唯一路径安全原语（跨切面原语，归 utils/ 更符合 §六）
    def safe_join(base: Path, *parts: str, *, suffix: str = "") -> Path:
        """受约束路径拼接：白名单字符 + resolve 前缀双重校验。
        任何越界 → 抛 PathTraversalError（VideoAgentError 子类，error_code="INVALID_PATH"）。"""
```

配套**机械门禁**（这是关键，否则同类漏洞会再犯）：
```
scripts/check_path_safety.py   → 登记进 acceptance.GATES
    规则：routes/**/*.py 中任何 `Path / f"{...}"` 或 `Path / var` 形式，
         其变量必须来自 safe_join() 的返回值，或显式标注 `# path-safety: validated`
         并说明校验位置。未标注即 FAIL。
```

并把 `repository.py::_project_dir` 的白名单 + resolve 校验**迁移到该原语**，成为全仓唯一样式。

## 三、S-2【HIGH】SSE 事件流与停止端点无鉴权

### 3.1 代码事实

`src/video_agent/web/routes/agent.py`：
- SSE 流端点（`:345-349`）返回 `StreamingResponse`，**不带任何 token 校验**；
- 停止端点（`:352-353`）`@router.post("/agent/tasks/{task_id}/stop")`，`async def stop_agent_task(task_id: str)`，**签名无鉴权依赖**。

### 3.2 影响

- SSE 事件体包含 `delta`（模型正文增量）、`reasoning_delta`（推理内容）、工具调用参数等 —— **等于实时旁路对话内容**；
- stop 端点可**停止他人的任务**（DoS）。

### 3.3 与鉴权中间件的关系（精确表述）

**注意**：这两个端点在 `/api/` 前缀下，因此**会**经过 `api_key_auth` 中间件（`app.py:225` 判定 `path.startswith("/api/")`）。所以：

- **生产模式**下二者受 `X-API-Key` 保护；
- **开发模式**下（`app.py:219-220` 直接放行）**完全无保护**。

**因此这条的准确级别是 HIGH 而非 BLOCKER**：它不是「绕过了鉴权」，而是「依赖全局中间件，且该中间件在默认模式下不生效」。

### 3.4 目标设计

- 鉴权应**分端点显式声明**（FastAPI `Depends`），而非仅靠全局中间件：`StreamingResponse` 与 stop 端点的 `dependencies=[Depends(require_api_key)]`，使「是否需要鉴权」在代码中**可见**，而非隐式继承中间件行为。
- 加门禁：`routes/**/*.py` 中每个 `@router` 装饰器必须要么声明 `dependencies=[...]`，要么在所属模块登记进「公开端点白名单」（只减不增）。这是防止「新增路由忘记鉴权」的机械保障。

| 序 | 动作 | 理由 |

## 六、复验方法与边界声明

**复验手段**（全部为只读）：
1. `read` 读取 `snapshots.py` 全部三个触及点、`repository.py` 对照实现、`app.py` 鉴权中间件；
2. 纯逻辑验证 `pathlib.Path` 前缀丢弃行为（**本地 Python 求值，未对任何服务发起请求**）；
3. `grep` 扫描 `routes/` 下同类 `Path / f"..."` 模式，确认影响面为 3 处；
4. `grep` 确认 `snapshots.py` 内**不存在** `_SNAP_ID_RE` / `re.match` / `resolve()` / `is_relative_to` / `startswith` 任一校验手段。

**我未做的事**（纪律声明）：
- **未对运行中的服务发起任何请求**（包括只读 GET）——避免在用户环境中留下探测痕迹或触发副作用；
- **未执行任何删除操作**。
- 因此本卷结论建立在**代码事实 + 语言语义**之上，而非实弹利用。代码事实链完整（无校验 → 拼接 → 读/删），判定为**确定的缺陷**。

**未确证项**：
- `web/url_safety.py` 的 SSRF 防护是否完整（未逐行复审）；
- 是否有反向代理/防火墙在本机 8080 之外提供额外隔离（部署信息不在仓库内）；
- `data/api_providers.json` 等目标文件在当前部署中的实际可读性（未探测）。
