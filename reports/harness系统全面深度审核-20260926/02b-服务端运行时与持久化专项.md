### 1.3 状态写入路径与持久性保证

**单一事实源 = SQLite**（`STATE_BACKEND` 默认 `"sqlite"`，config.py:377）：

```
StateManager.save()                       state/manager.py:489-495
  └─ save_ops.save(svc)                   state/save_ops.py:40-98
       ① read_index() 取磁盘 board_version（每次 save 都读一遍索引）

       ③ repo.save_project(pid, svc._raw_state)   → INSERT OR REPLACE INTO projects(id,state,updated_at)
       ④ repo.save_compat(...)                    → sqlite 后端为空实现
```

防抖：`save_debounced()` 置 `_save_dirty` 并起 `_debounced_flush`（`_SAVE_DEBOUNCE_SECONDS = 0.3`，
save_ops.py:25、:155-182）；无运行事件循环时退化为同步落盘（:163-167）；
`flush_save()` 取消在途防抖任务并同步写（:185-193）。

**实测耐久性数字（只读采样，2026-09-26 20:13–20:14）**：

| 项 | 实测值 |
|---|---|
| `workspace/state.sqlite3` | 6,504,448 B（≈6.20 MiB），`PRAGMA journal_mode = wal` |
| 表 | `projects(id,state,updated_at)` / `meta(key,value)` / `kv(key,value)` |
| 项目状态文档（活跃项目 proj-1790424553-d3395d49） | `length(state)` = **111,590 字符** = 218,636 B UTF-8；其中 2 条 `stateSnapshots` 约占 65.9 KB |
| 其他项目 | 24,551 / 30,183 / 20,940 字符（29.4 / 37.0 / 25.7 KB） |
| kv 载荷 | `generation_tasks` 1.9 KB、`agent_tasks` 0.3 KB；`meta.index` 212 B |
| 写入频率（40s 采样，服务空闲期） | WAL mtime/size 变化 **6 次**（t≈8.8/9.0/9.3/10.8/24.0/34.1s），单次 WAL 峰值 1,005,312 B，随后 checkpoint 归 0 |
| `data/agent_traces.jsonl` | **72.77 MB**（.env `TRACE_FILE_MAX_BYTES=104857600` 生效）；`.1/.2` 各 1.91 MB 且 mtime 停在 2026-09-07 / 09-06 |

增长方向是单调的（见 §三 S-07/S-08）。

| 机制 | 位置 | 作用域 |
|---|---|---|
| `svc.lock: asyncio.Lock()` | state/manager.py:168 | **实例级**（每 StateManager 一把，非全局） |

| `_known_version` 版本闸 | save_ops.py:64-71 | 跨实例「防旧盖新」乐观锁 |
| `_ACTIVE_LOOPS: Dict[str,int]` | core/agent_loop.py:106 | 会话级单驱动闸 |
| `_STOP_FLAGS: Dict[str,int]` 代际 token | utils/stop_signal.py:31-74 | 停止信号作用域 |
| `_INFLIGHT_REQUESTS: set`（非同步） | web/chat_opening.py:47-62 | 仅非流式端点 |
| `TaskStore._lock` / `SqliteStateRepository._lock` | task_store.py:36、repository_sqlite.py:70 | 各自实例的 `threading.Lock`，**互不相同** |
| `_SEQ_CACHE: Dict[str,int]`（非同步） | core/session_log.py:76 | 事件流 seq 分配 |

**关键事实（违反单写者假设）**：同一项目**同时存在多个 StateManager 实例**——
全局单例（`_instance_tag="global"`）与 N 个任务实例（`task:<project_id>`，manager.py:150/191）。
两者各持一份 `_raw_state` 内存副本、各持一把 `asyncio.Lock`（互斥不覆盖），并发整板写靠
`board_version` 事后闸丢弃其中一方，**不是互斥而是丢弃**。

## 三、缺陷与风险

> 严重度：blocker / high / medium / low。所有引用均为实读代码。

### S-01 【blocker】`snap_id` 未校验 → 任意文件读取（已实测）+ 任意文件删除

```python
# src/video_agent/web/routes/snapshots.py:112-120
def _read_snapshot(project_id: str, snap_id: str) -> Dict[str, Any]:
    f = _snap_dir(project_id) / f"{snap_id}.json"
    if not f.exists():
        raise VideoAgentError("快照不存在", status_code=404, error_code=LEGACY_NOT_FOUND)
    try:
        return json.loads(f.read_text(encoding="utf-8"))
```

```python
# src/video_agent/web/routes/snapshots.py:236-244
@router.delete("/conversations/snapshots/{snap_id}")
async def delete_snapshot(snap_id: str):
    ...
    f = d / f"{snap_id}.json"
    if not f.exists():
        raise VideoAgentError(...)
    f.unlink()
```

`snap_id` 直接来自 URL 路径参数，**无白名单、无 `resolve()` 前缀校验**；`Path("dir") / "C:\\abs"` 在
Windows 上丢弃前缀变绝对路径（已核 `pathlib` 语义）。对照 `repository.py:26,43-49` 对 `project_id`
有正则 + resolve 双重校验——快照域整条链路缺失同一层防护（`_snap_files`/`_prune_snapshots`
只对 `glob("*.json")` 生效，不参与路径构造）。
注：由于端点强制追加 `.json` 后缀，该缺陷的读取面为宿主上**任意已存在的 `*.json`**
（对 `data/api_providers.json`、`data/demo_state.json`、其它项目快照均已成立），
删除面同理限 `*.json`；非 `.json` 目标不可达。

**实证（只读 GET，本机在跑服务）**：

```
GET /api/conversations/snapshots/C%3A%5CUsers%5CASUS%5CAppData%5CLocal%5Cnpm-cache%5C_npx%5C1e7f6d9597241db0%5Cpackage
→ 200 {"dependencies":{"@deepseek-ai/dsh":"^0.1.5-rc.3"},"_npx":{"packages":["@deepseek-ai/dsh"]}}
```

即读出仓库外任意 `*.json`。同一构造用于 `DELETE` → 可删除宿主上任意已存在的 `*.json`
（如 `data/api_providers.json`）。**我未执行删除**（破坏性，保持只读审计纪律）。
`_snap_dir()` 的 `d.mkdir(parents=True, exist_ok=True)`（:41-44）使这两次探测在
`workspace/snapshots/<激活项目>/` 留下一个**空目录**（无文件写入）。

### S-02 【blocker】SSE 事件流与停止端点无任何凭据；事件体含模型原始输出与工具入参

全仓库 grep `busy_timeout` **0 命中**（仅 `journal_mode=WAL` 两处）。两套实例锁互不相同、

`StateError`（save_ops.py:96-98）——**而 41 处 `svc.save()` 调用点忽略返回值/不接异常**
（见 S-04），写入就此静默丢失。另：无 `synchronous` 设置，Windows 上 `os.replace` 断电不保证
目录项持久（fileio.py 已 fsync 文件但未 fsync 父目录）。

### S-04 【high】41 处 `save()` 调用点忽略版本闸结果，破坏性写入静默分裂

设计契约（save_ops.py:45-51 注释）明写「版本闸放弃写入时返回 False（调用方据此判冲突，
破坏性写入路径不得静默放行）」，但实测 grep：`^\s*(svc|self.state_manager|self)\.save(?:_async)?\(\)$`
共 **41 处**，仅 3 处检查返回值（chat_tail_ops.py:107、conversation_ops.py:165、batch_checkpoint.py:156-165）。
其中 8 处在 state 层正文：

```
src/video_agent/state/conversation_ops.py:304  ← cleanup_scoped_threads_for_removed（删除线程级联）
src/video_agent/state/conversation_ops.py:348  ← bind_thread_scope_refs
src/video_agent/state/conversation_ops.py:374  ← remove_thread_scope_ref
src/video_agent/state/conversation_ops.py:424  ← switch_conversation（重绑 chatMessages 引用）
src/video_agent/state/conversation_ops.py:439  ← delete_conversation
src/video_agent/state/manager.py:423           ← record_used_skill
src/video_agent/state/manager.py:436           ← set_active_skill
src/video_agent/state/undo_redo.py:68,78       ← undo / redo
（其余 33 处在 core/tools/web 层，含 tools/storyboard_tools.py ×7、
 tools/document_tools.py ×3、core/workflow_runtime.py ×5 等）
```

同文件的注释与实现也不一致：注释说「内存环形缓冲，不落盘」，实际 `_persist` 把
`"logs": self._gen_logs` 写进了 kv（:307-316）。

### S-21 【low】`AgentTracer` 全局流无上限汇总但落盘文件无界（配置层）

`_persist_record` 每次 `finish_trace` 都追加写（tracer.py:669-678），轮转阈值读
`settings.trace_file_max_bytes`；实测 `.env` 已改为 104,857,600（100 MB），
`TRACE_ROTATION_KEEP=10` → 上限 1 GB。当前 `data/agent_traces.jsonl` = **72.77 MB**，
`.1/.2` 的 mtime 停在 9/7、9/6（与「旧实现只滚到 n=1」的历史一致）。
`trace_retention_enabled` 默认关（config.py:356），且 `.env` 未开 → 72 MB 文件里的旧行
不会被压缩/丢弃。叠加 `SSE_CAPTURE=1`（data/sse_capture 每文件 1.2–1.7 MB，上限 500 个）。

### S-22 【low】`_INFLIGHT_REQUESTS` / `_BUCKET` / `_CACHE_SAMPLES` 等进程内注册表无跨进程语义

`live_metrics._LIVE/_SECTIONS/_BUDGET/_DEGRADATIONS/_CACHE_SAMPLES`（utils/live_metrics.py:19/38/63/87/129）
与 `stop_signal._STOP_FLAGS`、`agent_loop._ACTIVE_LOOPS`、`board_merge._BOARD_HISTORY`、
`chat_opening._INFLIGHT_REQUESTS` 全部是进程内 dict。`uvicorn --workers N`、多实例部署、
或 CLI + Web 同开时，忙闲闸/停止/快照基线**全部失效**。当前部署是单进程，属**架构性隐患**而非现网故障。

## 四、TARGET 设计（按缺陷给目标形态，不是补丁）

### T-01 统一「资源标识校验」为基础设施（治 S-01/S-19）
- **TARGET**：新增 `web/path_guard.py`，暴露 `resolve_child(base: Path, candidate: str, *, suffix: str) -> Path`，
  内部做 `Path(candidate).name == candidate`（拒 `/ \ ..` 与盘符）+ `resolve()` 后 `relative_to(base)` 双重断言，
  失败抛 `VideoAgentError(400, "INVALID_ID")`。
- 所有「用户可控字符串拼路径」的点（快照 id、project_id、asset 文件名、文档名）**只经此函数**；
  `state/repository.py` 的 `_PROJECT_ID_RE` 内联逻辑迁入同函数，形成单一事实源。
- 门禁：新增静态扫描（acceptance GATES）禁止 `Path(...) / f"{...}"` 形态出现在 `web/routes/**`。

### T-02 传输层鉴权与流隔离（治 S-02）
- **TARGET**：SSE 与任务控制端点改为**能力令牌（capability token）**模型：
  `POST /agent/tasks` 返回 `{task_id, stream_token}`（HMAC(task_id, 会话密文) 或一次性随机数存 kv）；
  `/events`、`/stop`、`/guidance` 必须带 `?st=` 或 `X-Stream-Token`，校验失败 401。
- 事件体分级：`tool_started.args` 默认只下发白名单字段（脱敏函数从 `core/tool_args_preview`
  提升为**传输层强制**，不是核心层自觉）。
- **TARGET**：所有 `/api/*` 无论环境都要求凭据；development 用「本机自动签发的短期令牌」
  （首次 HTML 加载时注入），把「开发便利」从「关掉认证」改为「自动凭据」。

### T-03 单一存储服务 + 单一锁域（治 S-03/S-10/S-18）
- **TARGET**：引入 `storage/connection.py::Database`：**进程内唯一** SQLite 连接管理器，
  `PRAGMA journal_mode=WAL; synchronous=NORMAL; busy_timeout=10000; foreign_keys=ON`，
  `TaskStore` 与 `SqliteStateRepository` 均改为**注入同一个 Database**（不再各自 `sqlite3.connect`）。
- **TARGET**：所有写路径收敛到 `StateManager.commit(mutation: Callable[[dict], None])`
  一个入口：锁内 apply + 版本闸 + 落盘，返回 `CommitResult(applied|conflict, version)`；
  `writeback_if_complete`、`board_merge`、`workflow_runtime`、各工具全部走它。
- **TARGET**：`asyncio.Lock` 改为在事件循环启动时**按循环重建**（`lifespan` 里 reset），
  或用 `anyio.Lock` 绑定当前循环。

### T-04 写路径分档：热/温/冷三档 + 事件溯源（治 S-04/S-07/S-08/S-09）
- **TARGET**：把 `_raw_state` 拆成三层：
  1. **热层（每操作即写）**：`state_events` 表（append-only，含 op/路径/值/actor/turn），
     单条 INSERT，天然原子；
  2. **温层（防抖合并）**：`board` 表按 `(project_id, category, id)` 行存，只写改动行；
  3. **冷层（轮末整板快照）**：`board_revisions` 表，每轮/每 N 秒一次逻辑快照，供回档。
  前端快照 = `revision + events since rev`，取代「整板 JSON 全量重写」。
- **TARGET**：`stateSnapshots` 从项目文档中**移出**（存 `snapshots` 表，按需 JOIN），
  彻底消除自嵌套与单文档膨胀；`_MAX_SNAPSHOTS` 改为字节预算。
- **TARGET**：`uploaded_docs` 正文移到 `documents` 表（已存在同名概念），状态文档只留指针
  （名/字数/hash）。

### T-05 任务与事件订阅的持久化模型（治 S-06/S-14/S-16）
- **TARGET**：订阅改为 **可续传日志流**：`task_events` 表 `(task_id, seq, type, payload_json, bytes)`，
  worker `emit` 先 INSERT 再 notify；`/events?from_seq=N` 从磁盘补发，慢消费者不再丢帧，
  只有「超出 retention 窗口」才要求重放并从最近 revision 重建。
- **TARGET**：背压按**字节**计：订阅者水位以未确认字节数计量，超限时暂停 worker 的 emit
  （await 语义）而非丢弃；终态帧不变（仍强投）。
- **TARGET**：任务「进行中态」也落库（`tasks` 表加 `progress_json` 列，每次 emit 更新），
  崩溃后前端可看到「断在哪里、已产出什么」，不再只有 `interrupted` 一句话。
- **TARGET**：`turn/start·turn/end` 改为**成对写在同一事务**（或引入 `turns` 表），
  崩溃时未闭合轮可由「孤儿 turn」扫描器显式判定，不靠 `finally`。

### T-06 幂等与并发控制（治 S-05/S-11/S-15）
- **TARGET**：所有有副作用的写端点接受 `Idempotency-Key`，在 `idempotency` 表
  `(key, scope) → (status, response_digest)` 落库；重放直接返回首次响应。
  `/agent/tasks` 必须支持（前端已在生成 request_id，只差后端消费）。
- **TARGET**：会话级 busy 判定与任务注册放进**同一个 `StateManager.commit` 临界区**
  （或 DB 层 `INSERT ... WHERE NOT EXISTS(SELECT 1 FROM tasks WHERE conversation_id=? AND status='running')`
  唯一约束），从「先查后建」改为「数据库级互斥」。
- **TARGET**：`svc.lock` 内**禁止** IO 与 LLM 调用：`_consume_pending_confirmation` 改为
  返回「待落盘变更集」，由 commit 统一写；`flush=True` 参数全部删除，flush 语义归 commit。

### T-07 状态投影单一化（治 S-11/S-19）
- **TARGET**：定义 **一个** `Projection.build(state, kind)`，kind ∈ `{board, full, agent_context, degraded}`；
  删除 `to_frontend_dict` 与 `ProjectState` 中从不持久化的字段，或让 `ProjectState` 成为
  `raw_state` 的**唯一 schema**（存什么就校验什么）。
- **TARGET**：`actions_applied` 帧携带 `state_rev`，前端与 `/conversations/{id}/projection`
  按 rev 判定落后（当前无任何版本对齐）。

### T-08 错误与密钥的传输边界（治 S-12/S-13）
- **TARGET**：`ErrorPayload.raw` 默认**不出传输层**：只有在 `ENVIRONMENT=development` 且
  请求来自回环时才附带；其余场景写日志与 trace，响应只给 `trace_id` 供人工溯源。
  `classify_exception(..., raw=...)` 的调用点在传输层统一 strip。
- **TARGET**：密钥存储抽象为 `secrets` 后端（默认：Windows DPAPI / Linux libsecret，
  回退「0600 权限的独立 keystore 文件」），`.env` 只保留非敏感配置；
  `update_env_key` 的「明文追加一行」形态退役。
- **TARGET**：中间件顺序固定为 `Origin/凭据 → 限流 → CORS`，限流对未认证请求也计数；
  `_Bucket` GC 改为定时任务而非路径触发。

### T-09 事件流与 trace 的保留策略（治 S-21/S-22）
- **TARGET**：`sessions/*.jsonl` 引入轮转 + 归档（压缩后的 `.jsonl.gz`），
  单文件设字节上限并按 `(project, conversation, seq range)` 维护索引；
  `load_events` 支持「从 seq 读」而非全文件读。
- **TARGET**：`trace_retention_enabled` 默认开，`agent_traces.jsonl` 上限回到 2–20 MB 区间；
  `SSE_CAPTURE` 加「自动过期」而非依赖人工关。
- **TARGET**：所有进程内注册表（忙闲闸/停止/快照基线/inflight）明确标注为「单进程假设」，
  并在启动时检测 `--workers > 1` 直接拒绝启动（fail fast），而不是静默失效。
