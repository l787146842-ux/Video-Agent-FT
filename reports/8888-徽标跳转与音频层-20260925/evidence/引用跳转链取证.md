# 分镜卡片「引用:」chip 点击跳转不稳定 — 排查报告（只读，未改任何代码）

## 一、结论（每条一句话）

1. **主因**：`jumpToElementByTitle` 用**逐字比对**（`k.title === title || k.id === title`），而真实数据里关键元素标题一律带 `Element_` 前缀、shotRefs 43/47 存**裸名** ⇒ 绝大多数点击直接查不到，只弹 toast，不跳转。
2. 这不是玄学：**能不能跳完全由该条 shotRefs 当年被写入时的字面形态决定**（`Element_x` 能跳 / `x` 不能跳），同一元素的同一个可见 chip 在不同分镜里一个能跳一个不能 ⇒ 「有时跳有时不跳」。
3. **次因（独立第二致因）**：跳转的落地依赖 `StoryboardView` 已挂载且 rAF 回调里能查到 DOM 节点，而 `StoryboardView` 只在 `leftTab === 'storyboard'` 时挂载（`LeftPanel.tsx:49`）——若左栏正停在「未归类素材」或被响应式收起（`AgentLayout.tsx:62`），store 状态照样更新但**滚动/闪烁静默丢弃**，同样表现为「点了没反应」。
4. 失败时用户看到的是 toast「未找到关键元素「程心」」（`ui.ts:132`，3 秒自动消失），无 i18n key。
5. **测试全是假的绿**：组件/ store 测试里的 keyElements 标题都是裸名（`'程心'`/`'少女'`），恰好与裸名 shotRefs 逐字相等，所以永远测不出这个 bug。
6. 前端存在 canonical 单一事实源（`stripTypePrefix`）且**展示层、缩略图、后端读口都用了它，唯独点击跳转这条链没用** ⇒ 典型的「同一规则多处各写一遍」口径漂移（与后端 2026-09-23 批10 事故 4444/P0-A 同源）。

## 二、证据（file:line + 引文）

### 1) 跳转是逐字比对（问题根因）
`src/web/stores/studio/ui.ts:129-134`
```ts
jumpToElementByTitle(title: string) {
  const el = state.keyElements.find((k) => k.title === title || k.id === title);
  if (!el) {
    showToast(`未找到关键元素「${title}」`, 'warning');
    return;
  }
```
同一函数 135-143 只做 `leftTab='storyboard' / subTab='keyElements' / locateGroupId=el.id / locateTick++`，再无别的兜底。

点击传入的是**存储原值**，不是显示标签：
- `src/web/components/left-panel/group-card/ShotRefsChips.tsx:81`
  ```tsx
  onClick={() => studioActions.jumpToElementByTitle(String(ref))}
  ```
- `src/web/components/left-panel/group-card/ShotDescEditor.tsx:143-146`
  ```tsx
  const chip = (e.target as HTMLElement).closest('.mention-chip') as HTMLElement | null;
  if (chip) { studioActions.jumpToElementByTitle(chip.dataset.name || ''); }
  ```
  正文 chip 的 `dataset.name` 是**裸名**（`desc-ref-utils.ts:99-101` 把 `stripTypePrefix(raw)` 也塞进候选名），所以正文内联块这条路**100% 点不到**（标题是 `Element_程心`）。

可跳/不可跳的精确判定（关键元素标题恒为 `Element_<name>`，见 `storyboard_ops.py:182-186`）：
| 存储形态 | 是否命中 | 依据 |
|---|---|---|
| `Element_程心` | ✅ 命中（逐字等于 title） | `ui.ts:130` |
| `ke-1790327083-...`（组 id） | ✅ 命中（逐字等于 id） | `ui.ts:130` |
| `程心`（裸名） | ❌ 查不到 → toast | `ui.ts:130,132` |
| 其它 Shot_/Audio_ 标题 | ❌（只搜 keyElements） | `ui.ts:130` |

### 2) 三源合并决定了「裸名 vs 带前缀」混合（后端事实）
`src/video_agent/state/storyboard_ops.py:717-730`（`merge_shot_refs`，仅此一处实现，`storyboard_tools.py:359`、`fc_gates.py:305` 共用）
```python
explicit = [r for r in (explicit_refs or []) if str(r).strip()]
tokens = parse_element_tokens(desc or "")
matched_titles, _unmatched = match_element_titles_report(state, tokens)
bare_hits = scan_bare_name_mentions(desc or "", state.get(CAT_KEY_ELEMENTS, []))
for ref in list(explicit) + matched_titles + bare_hits:
    key = strip_type_prefix(str(ref))
```
- ② `[令牌]` 源与 ③ 裸名提及源返回的都是**组标题（带前缀）**：`match_element_titles_report` 取 `g.get("title")`（`:740-756`），`scan_bare_name_mentions` 结尾 `hits.append(title)`（`:679-681`）。
- ① 显式 `shot_refs` **原样透传**——模型重抄时写什么就是什么。
⇒ 因此**裸名只可能来自 ① 显式源**；一旦某镜的 ref 走 ① 而模型写裸名，该 chip 必点不动。`dedup_shot_refs` 只做 canonical 去重（`:160-174`）**不改写形态**，补丁写口也不归一（`:425-426`）。后端早已把这条口径固化为读口唯一入口：`canonical_ref_key`/`find_ref_group`（`:216-254`）。

### 3) 第二致因：DOM/挂载依赖 + 双 rAF 静默丢弃
`src/web/components/left-panel/StoryboardView.tsx:108-131`
```tsx
createEffect(() => {
  const tick = state.locateTick;
  if (!tick) return;
  // 等 subTab 切换后的重渲染完成，再查找目标 DOM
  requestAnimationFrame(() => requestAnimationFrame(() => {
    const gid = state.locateGroupId;
    let target: HTMLElement | null = null;
    if (gid) {
      target = Array.from(containerRef?.querySelectorAll<HTMLElement>('.sb-group') || [])
        .find((g) => g.dataset.groupId === gid) || null;
    }
    if (!target) {
      target = containerRef?.querySelector('.draft-card.active') as HTMLElement | null;
    }
    if (!target) return;                       // ← 静默 return，无任何提示
```
- **2 次 rAF 等待**（`:112`），失败无 toast（`:123`）。
- `containerRef` 是组件内局部变量（`:99`），只在 StoryboardView 挂载时存在；`containerRef?.` 在未挂载时求值为 `undefined` ⇒ 同样走到 `:123` 静默返回。
- StoryboardView 挂载条件：`LeftPanel.tsx:47-55` 的 `Switch/Match when={state.leftTab === 'storyboard'}`；左栏整体再被 `AgentLayout.tsx:62-67` 的 `<Show when={!leftCollapsed()}>` 包着（≤1100px 自动收起，`:32-36`）。
- 触发时 `jumpToElementByTitle` 会先 `setState('leftTab','storyboard')`（`ui.ts:135`），但 Solid 的 `<Switch>` 重挂 + `<For>` 渲染需要时间/微任务窗口；若该次渲染落空（例如 keyElements 为空、或窗口 <1100px 左栏收起、或查询时分组尚未渲染），状态已变、DOM 不存，跳转**静默失败**。
- `locateTick`/`locateGroupId` 定义与初值：`studio-core.ts:50-52, 91-92`；`locateTick` 只在此 effect 消费（grep 全仓仅 `ui.ts:48,143` 写、`StoryboardView.tsx:109` 读）。

### 4) 失败的可见反馈
`src/web/stores/studio/ui.ts:132`
```ts
showToast(`未找到关键元素「${title}」`, 'warning');
```
`showToast` 默认 3000ms 自动消失、无 i18n key（`src/web/stores/toast.ts:21-32`），宿主全局挂载于 `src/web/components/layout/LayoutShell.tsx:234 <ToastHost />`。而第二条路径（`:123` 的 return）**没有任何提示**——这正是「没反应」与「弹未找到」两种现象并存的解释。

### 5) 平行实现对比：canonical 助手存在，唯独点击链绕过
`src/web/lib/desc-ref-utils.ts:32-38`
```ts
export function stripTypePrefix(title: string): string {
  const t = String(title || '').trim();
  for (const p of TYPE_PREFIXES) { if (t.startsWith(p)) return t.slice(p.length); }
  return t;
}
```
- 展示层（chip 文案）：`ShotRefsChips.tsx:19-23` `normalizeDisplayTitle(rawResolve(ref))` —— **canonical**（所以用户看到的每个 chip 文案都正常，掩盖了存储形态差异）。
- 缩略图：`desc-ref-utils.ts:107-111` `elementThumb` —— **canonical**
  ```ts
  const norm = stripTypePrefix(title);
  const el = keyElements.find((k) => stripTypePrefix(k.title || '') === norm);
  ```
- 引用→标题：`desc-ref-utils.ts:49-52` `resolveRefTitle` —— find 也是逐字（`:50`），但**回退值 `stripTypePrefix(el?.title || String(ref))` 使它对带/不带前缀都恰好正确**（展示口径因而免疫）。
- 后端读口：`storyboard_ops.py:216-222 canonical_ref_key` + `:241-254 find_ref_group`（注释 `:244-246` 明写「读口唯一入口 …杜绝同一条引用链各写一遍比对式」）。
⇒ **单一实现违规**：前端已有 canonical 助手，跳转链（`ui.ts:130`）与 `ShotRefsChips.tsx:81`/`ShotDescEditor.tsx:145` 未走它；后端早已把同类 bug 定性为「写口与读口口径漂移」（`storyboard_ops.py:198-213`）。

## 三、数据统计（GET http://127.0.0.1:8080/api/project/state，只读；探针 `.tmp_probe/probe_refs.py`、`probe_refs2.py`，输出 `refs_report.txt` / `refs_report2.txt`）

- 规模：keyElements **14**（标题 **14/14 带 `Element_`**，0 个裸名）/ shots **10** / audioItems 3。
- shotRefs 共 **47** 条：**带 `Element_` 前缀 4 条（8.5%）**、**裸名 43 条（91.5%）**、命中组 id 的 **0** 条。
- 按 `ShotRefsChips.visibleRefs` 去重口径复算（每镜可见 chip）：**可见 chip 47 个 → 可跳 4 个（8.5%）、点击必失败 43 个（91.5%）**。
- 逐镜（存储条数 → 去重可见 chip / 点击必失败数）：3→0/3、4→0/4、5→1/4、4→0/4、5→1/4、5→0/5、7→2/5、3→0/3、6→0/6、5→0/5。**10/10 分镜都至少有一个点不动的 chip**。
- 最刺眼的「不稳定」实证：**同一个元素 `白色薄片`**，在 shot `Shot_程心追问打击…` 存 `Element_白色薄片` → **能跳**；在 shot `Shot_太空艇抵近目标…`、`Shot_机械臂伸向薄膜…`、`Shot_瓦西里戴手套…`、`Shot_二十多小时过去…` 存裸名 `白色薄片` → **不能跳**；`程心`/`AA`/`木星轨道「星环」号球形舱` 同理。
- 同一元素两形态并存者 **4/14**（`程心 4裸+1前缀`、`AA 4+1`、`白色薄片 4+1`、`木星轨道「星环」号球形舱 4+1`）；单镜内并存 0（被 `dedup_shot_refs` 去重）。
- 对照：对同一份 state 调后端读口 `find_ref_group` ⇒ **47/47 全部命中**。即「后端全命中、前端点击 4/47 命中」——两侧口径差 = 前缀。

## 四、修复方向建议（不改代码，只指位置）

1. **跳转比对照搬 canonical 键**（首选，最小面）：`src/web/stores/studio/ui.ts:130` 改为 canonical 命中，例如
   `const norm = stripTypePrefix(title); const el = state.keyElements.find(k => k.id === title || stripTypePrefix(k.title || '') === norm);`
   —— 与后端 `canonical_ref_key`（`storyboard_ops.py:216-222`）、前端 `elementThumb`（`desc-ref-utils.ts:107-111`）同口径。
2. **把 canonical 解析收进单一入口**：在 `src/web/lib/desc-ref-utils.ts` 里新增/复用一个「ref → 关键元素组」的解析函数（`resolveRefElement(ref, keyElements)`），让 `ui.ts:130`、`ShotRefsChips.tsx:20`、`ShotDescEditor.tsx:145` 三处共用，避免第四份比对式（后端注释 `:244-246` 已把「各写一遍」定性为事故成因）。
3. **补上静默失败的可见性**（第二致因）：`src/web/components/left-panel/StoryboardView.tsx:123` 的 `if (!target) return;` 应有兜底（例如目标分组不在当前 subTab 列表时给出提示，或改为等待分组出现而非一次性双 rAF 丢弃）；同时评估 `jumpToElementByTitle`（`ui.ts:135`）在 `leftTab !== 'storyboard'` / 左栏收起时的落地策略。
4. **测试口径修正**（防回归的关键）：现有用例的 keyElements 标题都是裸名，等于绕过了前缀契约——`src/web/stores/__tests__/studio.test.ts:8-15, 98-102`、`src/web/components/__tests__/ShotRefsChips.test.tsx:35-39`、`src/web/components/__tests__/ShotDescEditor.test.tsx:40-43` 应加入 `title: 'Element_程心'` 且 shotRefs 为裸名 `'程心'` 的用例（两个方向都要：裸名 ref → 带前缀 title、带前缀 ref → 带前缀 title）。
5. **数据层可选**：`merge_shot_refs`（`storyboard_ops.py:717-730`）与 patch 写口（`:425-426`）可考虑把 ① 显式源也归一到 canonical 形态（现只去重不改写），这样前端即便逐字比对也能命中；但按 P1 应优先修读口（第 1、2 条），写口归一属数据契约变更，需另行裁决。

> 备注：本次仅新增两个只读探针与输出文件于 `.tmp_probe/`（`probe_refs.py`、`probe_refs2.py`、`refs_report.txt`、`refs_report2.txt`），**未修改任何项目源码**。
