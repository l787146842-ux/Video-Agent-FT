# 音频层"故事板设计期建卡"契约冲突调查

只读调查，未改任何仓内文件；探针见 `.tmp_probe/audio_*.py`。8888 数据 = `.tmp_probe/projects/proj-1790326837-3c760e66.json`。

## 结论

1. **是平台放行，不是模型越权。** `storyboard_design` 建卡白名单 = `{"audio","video"}`，闸机只看 `mediaType`，**完全不区分 `audioType`**——BGM / 旁白 / 音色卡同路放行（实测见 §1）。⇒ **当前平台明确允许故事板设计期建 BGM 卡。**
2. **模型收到的字段契约比 Skill 更鼓励建卡**：`_DRAFT_FIELDS_HINT` 把 `bgm/narration` 与 `voice` 并列、"音频卡两个都标"；矩阵把 `audio` 渲染成"可放音频；可出音频"。模型建卡是**照契约执行**。
3. **Skill 层是本项目自己改坏的。** flova 原文写 `使用 **text_to_instrumental**，推荐模型：**Suno 5**`（全篇无"草稿"）；现文改成"…**按草稿配置产出**"——这句**预设草稿卡存在**。git `7bb5a672`（"幻影工具名清偿"）顺手引入，**无任何裁决留痕**（全仓 grep"按草稿配置"于 docs/CHANGELOG = 0 命中）。
4. **两条同源静默失效**：音频组 `desc` **不进模型快照**（模型只见 `prompt_chars:0`+卡列表）；前端描述位读 `prompt` 不读 `desc` ⇒ 用户 146 字描述显示为"双击添加描述…"。用户看到的空与模型看到的空来自两处不同缺陷，指向同一事实：**`desc` 在音频类目是孤儿字段**。
5. **音频生成消费的是卡**（`draft.prompt`，且回写同卡），平台**没有真实音频生成通道**。⇒ 若故事板期不建卡，必须先在音频生成阶段补"描述→卡"的承接，否则功能断链。
