## §2 外部依据：DSH 主源码的同款修复（方法论锚点）

> **源码位置**（**只读，未做任何修改**）：`E:\07 天问\deepseek-harness-master`

### 2.1 设计笔记（逐字引证）

**文件**：`.agents\notes\archived\bug-fix\2026-08-19-deepseek-reasoning-passback-every-turn.zh.md`

**问题（L10–L12 逐字）**：

> `dsh-llm-deepseek` 只在**同时携带工具调用的 assistant 轮次**上，才把 `reasoning_content` 回放进历史。…但该端点不是这个适配器唯一服务的对象。…这类网关在协议上没有承载上游思考签名的字段，只能对回放的思维链取哈希来恢复它。于是**模型未调用工具就作答的轮次到达网关时完全不带推理文本**，签名查找落空，**重建出的对话与记录中的对话产生分叉**。Agent 运行的大多数轮次都会调用工具，所以**这个损失只在纯作答轮次上出现，表现为偶发**。

**修复决定（L16 逐字）**：

> `serializeAssistant` **对每个内容携带推理的 assistant 轮次都发出 `reasoning_content`，与是否有工具调用无关。没有推理块时仍然不发出该字段**，因此非思考轮次的行为不变。

### 2.2 实现（逐字引证）

**文件**：`packages\llm\llm-deepseek\src\protocols\chat-completions\serialize.ts`

**L210–L228 关键段**：

```typescript
  return {
    role: 'assistant',
    // Text-less turns send "" — NEVER null. ...
    content: text,
    // CoT passback on every reasoning-carrying turn. The official rule
    // (guides/thinking_mode.mdx) requires it on tool-call turns and ignores it
    // elsewhere; a gateway re-encoding the conversation for another vendor
    // recovers that turn's upstream thinking signature by hashing this exact
    // text, which a tool-call-free turn carries nowhere else.
    ...reasoning.length > 0 ? { reasoning_content: reasoning } : {},
    ...toolCalls.length > 0 ? { tool_calls: toolCalls } : {},
  }
```

> **★ 形态同构性（逐项）**：

| 维度 | DSH | 本仓 9999 |
|---|---|---|
| **缺陷** | 只在**带工具调用**的 assistant 轮次回传 reasoning | 只在 **FC 工具轮**（L674–680）带 reasoning；**纯文本续跑轮**（L765）不带 |
| **后果** | 纯作答轮丢推理 → **会话重建分叉** | 续跑轮丢推理 → **草稿丢失、从零重拟** |
| **为何偶发** | 「大多数轮次都会调用工具，损失只在纯作答轮出现」 | **同理**——正常工具轮不受影响，只有假停续跑轮（少数）丢稿 |
| **修法** | 每个携带推理的轮次都发出该字段 | **同**——L765 补齐到与 FC 分支同口径 |
| **边界** | 无推理块时**仍不发**该字段 | **同**——`strip()` 后为空即不设键 |

### 2.3 ★ 正面回应「DSH 否决了开关策略」

**DSH 的否决（该笔记 L22 逐字）**：

> **用 `Config` 开关选择回传策略。** 两种端点行为都真实存在，但该字段在不需要它的地方是惰性的，所以这个开关最多只换回一个轮次的思维链输入 token ——代价却是一旦设置错误，**会话就会静默地无法重建，两端都不会报错来归因**。**一个设错就静默失败的旋钮，比那点 token 更糟。**

**本仓的处置（正面回应，三条）**：

1. **本修复不新增开关** —— 沿用**既有** `settings.llm_reasoning_passthrough`（`config.py` **L147–L148** 默认 `False`；本机 `.env` **L1** 显式设 `=1`）。**未引入任何新的配置旋钮** → **与 DSH 的否决不冲突**。
2. **本修复同时消除了一处「静默不一致」** —— 修复前，**同一个开关**在 FC 分支生效、在续跑分支失效（**同门控、同变量、同文件，行为相反**）。DSH 反对的是「**新增一个可能设错的旋钮**」；本修复做的是「**让既有旋钮在两个分支上行为一致**」——**方向相反**。
3. **边界诚实标注** —— DSH 的否决理由中「**静默失败、两端都不报错**」这一点，本仓**原本就已存在**（且正是本次事故的形态）：9999 丢稿时**平台无任何告警**，只在产物层面表现为规格膨胀。本修复**减少**该静默面（续跑分支不再是例外），但**不消除**闸门本身「设错即静默」的固有属性——**该属性属既有闸门设计，不在本任务改动面内**。

```python
import os, pathlib
_RELAX = {0o700: 0o755}
_orig = pathlib.Path.mkdir
def _mkdir(self, mode=0o777, parents=False, exist_ok=False):
    return _orig(self, mode=_RELAX.get(mode, mode), parents=parents, exist_ok=exist_ok)
pathlib.Path.mkdir = _mkdir
_os_mkdir = os.mkdir
def _osmkdir(path, mode=0o777, *a, **kw):
    return _os_mkdir(path, _RELAX.get(mode, mode), *a, **kw)
os.mkdir = _osmkdir
```
