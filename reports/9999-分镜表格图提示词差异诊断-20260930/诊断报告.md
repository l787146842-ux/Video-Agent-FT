## 0. 一句话结论

**不是模型不听话，是模板给的"槽位"不够。** 模板里**没写**的东西，模型要么整段丢掉（时长），要么自己发明（画风、图例细节）；Flova 的模型在同样的模板上**自己补齐了**这些槽位，所以看起来"它的更好"。⇒ **修模板 = 把 Flova 靠自觉补的东西，写成模板里的硬槽位。**

## 3. 根因链（三句话）

```
① 模板只给「三段式骨架」+「四处该给的值没给」（时长/画法/图例形状/负向约束）
      ↓
② 模型策略是「有槽位就填，没槽位不动」——照抄模板 ⇒ 该有的要素整块缺席
      ↓
③ Flova 的模型主动补齐了骨架外的要素（Panel 自足、时长、线稿、LEGEND BOX）
   ⇒ 同模板、不同产物；差距 = 模型的「自觉」vs 模板的「完备度」
```

**证据强度**：
- 「时长」是**最强证据**——Skill 散文 `:130` 明写「分镜表格图需包含四大要素：…景别与时长标注…」，但模板 `:196-200` 的三段式**没有时长槽位**；本地 11/11 张卡**全漏**，Flova 每格都有 ⇒ 模型不补散文要求，只填模板槽位。
- 「画法」是**次强证据**——`line art`/`drafting` 两个词在**本地与 Flova 两份 skill 里都是 0 处命中**（实测）⇒ Flova 那句是**它自己的模型发明的**（或它运行时用了比桌面留档更新的 skill）。**这决定了修改方案的性质：我们不是在"抄 Flova 的模板"，而是在"把 Flova 的产物规范固化成我们的模板"。**

## 4. 修改方案（大白话版）

### 总原则

> **模板里给足槽位 = 模型不用猜。** 散文要求（Skill 第 130 行那类）模型不照着做；只有把要求变成模板里的**具体位置**，它才会填。

### 方案 A：只改 Skill 文本（零代码，改动 1 个文件）

改 `data/skills/AI-短剧一站式生成/SKILL.md` 的**表格图模板段**（现 190-212 行）+ **要素清单段**（现 130 行）。逐条对应：

| 改哪 | 现在 | 改成 |
|---|---|---|
| **① 画布比例** | `vertical 3:4 layout` | `Layout: single 16:9 landscape image divided into 3 equal vertical panels side by side, each panel framed with a thin black border` |
| **② 画法** | `frame thumbnails photorealistic, …超写实科幻电影感` | `pure black line art, technical drafting aesthetic, no photorealistic rendering, no watermark, no subtitles`（保留 `matching attached reference images exactly`） |
| **③ 时长槽位** | 三段式无时长 | `Left (10%): numbered circle + Chinese shot description (景别 + 动作摘要 + 时长, 2–3 行)`，或把行首改成 `Row N — 【景别: … ｜ 时长: …s】` |
| **④ 图例形状** | 只给颜色 | `legend box: 推进=red dashed arrow, 拉远=blue dashed arrow, 环绕=green dashed arrow, 升降=yellow dashed arrow, 跟随=purple dashed arrow, 固定=gray filled circle` |
| **⑤ 相机位姿** | `camera icon 📷 marks start position` | `camera icon 📷 placed at [位置], angled [上/下/平]（如 lower-left, angled upward）` |
| **⑥ 中文注记块** | 无 | `Right (20%)` 之下加一行：`Chinese annotation block: '[景别+运镜 / 主体动作 / 光影要点]'` |
| **⑦ 负向约束** | 无 | 段末加 `No text, no labels, no watermark.` |
| **⑧ 正文引用记号** | 尾部 `@[角色代号]` 占位句 | 正文里凡提到关键元素处**用 `@元素真实名`**（平台自动转 `[参考图N：名称]`）；尾部清单保留但注明"名称须与关键元素标题一致" |

**风险**：`skill_anchor_lint` 是门禁（技术门禁表里有），改 Skill 后必须跑；改动不得删除被门禁锚定的句子（改前先跑一次确认锚点位置）。

### 方案 B：方案 A + 引导模型在正文写 `@`（你已裁决的第一层）

方案 A 的第 ⑧ 条只解决了"模板怎么写"，还需要模型**执行**。落点：`write_media_prompt` 阶段的任务书/Skill 章节里给一句正面契约（"正文提到关键元素时写 `@名称`"）。平台机制已就绪（`resolve_prompt_mentions` 两式同轨），故这层**零后端改动**。

### 方案 C（不建议现在做）：平台强制注入

由平台在生成前把正文里的元素名自动改写成 `@名称`。对模型零要求，但新增一处"正文改写"逻辑，且与"平台改写必须模型可见"的新宪法条款要额外对齐——**建议先看方案 A+B 的实跑效果再定**。

### 建议的验证方式

改完模板后，**只重跑 1 张卡**（如 S11），生图后按 §2 的 9 个维度逐项目测；不要一次重跑 11 张（费钱且噪音大）。
