## 〇、执行摘要（先看这段）

本平台的 `@`/`<<<image_>>>` 引用解析之所以对 flova 抄来的 Skill **基本失效**，有**三个互相独立**的原因，任一条都足以让引用落空：

| # | 根因 | 位置 | 后果 |
|---|---|---|---|
| **R1** | `_MENTION_RE` 的 `[@＠]([^\s@＠]+)` 把方括号一起吞进捕获组，`@[程心]` 变成待查键 `"[程心]"` → 查不到 | `src/video_agent/core/prompt_refs.py:22`、`:97` | `@[角色代号]` 这一 flova 模板写法 **100% 解析失败** |
| **R2** | Skill 里 `<<<image\_场景>>>` 的下划线是 **Markdown 转义**（`\_`），而正则 `<<<\s*image_` 要求裸下划线——`image\` 后面跟的是 `_`，字面多了一个反斜杠，**整个记号连正则都不匹配** | `data/skills/AI-短剧一站式生成/SKILL.md:223,225`、`prompt_refs.py:22` | **模型逐字复制模板也解析失败**；且因未被 `sub` 触及，`<<<image\_场景>>>` 原样进入生成请求 |
| **R3** | 平台建组时**幂等补类型前缀**（`Element_程心`），而模型的提示词用**裸名**（`<<<image_程心>>>`）；`build_storyboard_media_map` 只注册带前缀的 `g.title` | `src/video_agent/state/storyboard_ops.py:83-89`、`storyboard_tools.py:188`、`prompt_refs.py:70-71` | **实跑中 110 次占位符引用，命中 0 次**（全量会话取证） |

唯一的安慰：R1/R2/R3 无论哪条，命中失败时正则**会把记号整个删掉只留名字文字**（`prompt_refs.py:100`），所以不会把 `<<<image_程心>>>` 这种原始记号直接喂给模型——但也就**到此为止**，参考图不会自动挂上。

**结论一句话**：flova Skill 里的引用层（`@[...]`、`<<<image_...>>>`）在本平台**结构性不可用**；平台实际依赖的是另一条通道（分镜组的 `sceneRefs` 自动挂参考图 + 前端 `@` 面板 chip），而 Skill 里**没有任何一句话**在教模型用这条通道。

## ① `@角色代号` 解析结论（含实测）

### 1.1 后端 `_MENTION_RE` 认哪些形态

`src/video_agent/core/prompt_refs.py:18-22`：

```python
# 引用记号匹配（两式同义，2026-09-07 外部标杆 记号兼容裁决）：
# 1) 半角 @ 或全角 ＠ + 非空白/非@字符（平台原生，前端 PromptEditor 序列化产物）；
# 2) <<<image_名称>>>（外部标杆 Skill 模板方言）——抄自 外部标杆 的 Skill 原样可用，
#    命中与 @ 同轨处理，未命中同 @ 去记号留名称。
_MENTION_RE = re.compile(r"<<<\s*image_([^<>]+?)\s*>>>|[@＠]([^\s@＠]+)")
```

| 形态 | 是否被匹配 | 捕获组内容 | 证据 |
|---|---|---|---|
| `@名称` | ✅ | `名称`（无 @） | `prompt_refs.py:22` + `tests/unit/test_prompt_refs.py:12-16` |
| `＠名称`（全角） | ✅ | `名称` | `prompt_refs.py:22` 字符类含 `＠` |
| `<<<image_名称>>>` | ✅ | `名称`（`group(1)`） | `prompt_refs.py:22` + `test_prompt_refs.py:19-24` |
| `@[名称]`（方括号） | ⚠️ **匹配，但捕获组含方括号** | `[名称]`（**带括号**） | 见 1.2 实测 |
| `<<<image\_名称>>>`（下划线被 Markdown 转义） | ❌ 不匹配 | —— | 见 1.4 实测 |

**关键机制**：`[@＠]([^\s@＠]+)` 的排除类只有「空白」和「@/＠」两种字符，**方括号不在排除类里**，因此 `[` 和 `]` 都会被 `+` 吃掉，落进 `group(2)`。而查表用的是 `media_map.get(name)`（`prompt_refs.py:98`），键是**元素标题原文**（如 `程心` / `Element_程心`），不可能等于 `"[程心]"`。

### 1.3 前端 `src/web/` 的 `@` 解析实现

两处，**前后端口径不一致**：

| 文件 | 正则 | 认 `@[方括号]`？ | 认 `<<<image_>>>`？ |

- 两条路径入口不同：Agent 路径走 `generation_submit.py`（后端解析，`:86-89` / `:342-346`），手动点「生成」走前端 `generate-actions.ts:38` / `:101`。

## ② `replicate exactly` 结论

### 2.1 这句话有没有传给生成模型？

**分两种情况，都不达意**：

- **`@[...]` 形态（没命中，100% 现实）**：`@[角色代号]` → `[角色代号]`（只掉了 `@`），`replicate exactly` 这半句**原样留在提示词里传给生成模型**。于是模型看到的是一句「Character sheet for [程心] — replicate exactly」——**要它精确复制一张根本没随请求发过去的图**。
- **`<<<image\_场景>>>` 形态（连正则都不匹配）**：整段**完全没被 `sub` 触及**，`<<<image\_场景>>>` 与 `replicate exactly`（如果有）**逐字原样**进入生成请求。
- **如果侥幸命中**：`resolve_prompt_mentions` 会把 `@名称` 换成 `[参考图N：名称]`，但**不碰** `replicate exactly` 这半句（`prompt_refs.py:96-111` 只替换匹配段）。

即：**无论哪条路径，`replicate exactly` 都未被任何代码识别为"约束"**。

### 2.2 平台有没有任何代码引用/依赖它？

**未找到。** 检索记录：

| 搜索关键词 | 范围 | 命中 |
|---|---|---|
| `replicate` | `src/**` | 0（`src/video_agent` 与 `src/web` 全无） |
| `exactly` | `src/**` | 0（同上） |
| `保真` | `src/**` | 5 处，**全部**是前端会话保真/组件行为保真注释（`subagent-actors.ts:270`、`Lightbox.tsx:138` 等），与图像生成无关 |
| `参考强度` / `strength` / `fidelity` / `denoise` | `src/**` | 0（仅有 SSE `guidance_injected` 的误命中，无关） |

全仓唯一的「保真」相关性来源是 `src/video_agent/adapters/openai_compat.py:1024` 的一句**平台自造**提示词：

```python
ref_hint = " The attached image(s) are provided as visual references; keep the result consistent with them." if reference_images else ""
```

这是**平台固定模板**，与 Skill 是否写 `replicate exactly` 无关，且语气远弱于 `replicate exactly`。注意它只在 `_try_chat_fallback`（chat/completions 兜底路径）里加；`images/generations` 主路径（`openai_compat.py:949-966`）并不加这句。

| 面 | 参数 | 位置 |

**确证**：`role` 是平台唯一的"参考图语义"通道，而它只有**位置语义**（首帧/尾帧/主体参考），**没有强度/保真语义**。`replicate exactly` 无处落。

### 2.4 它本该怎么用

结合 `image_generate` / `generate_video` / `MultiModalToVideo` 的参考图机制，有两条现实路径（按本平台能力排序）：

**路径 A（零成本，立即可做）——把约束留在提示词层，但配上正确的位置标记**
现在平台已经把引用重写成 `[参考图N：名称]`（`prompt_refs.py:109`）。`replicate exactly` 需要的只是**与 `[参考图N]` 同句**：
```
- Image 1: Character sheet for [参考图1：Element_程心] — replicate exactly
```
这一句本身对模型就是有效约束（多模态模型能看到第 1 张附件）。**当前它失败的唯一原因是引用没挂上（R1/R2/R3），而不是这句话没用。** 修 R1/R2/R3 即可恢复该句的效力。

**路径 B（有平台承载，需接线）——落到 `role` 通道**
`video_compat.py:55-62` 的 role 闭集里已有 `subject_reference`，语义上最接近「精确复制这个主体」；且 `role` 已经逐项写进请求体（`video_compat.py:504-526`）。可以让 flova 语义映射到 role：

| flova 写法 | 建议 role | 说明 |
|---|---|---|
| `replicate exactly` + Character sheet | `subject`（→`subject_reference`） | 主体身份复制 |
| `replicate exactly` + Location sheet | `reference`（→`reference_image`） | 场景/背景复制 |
| `<<<image_reference_frame>>>`（限制为背景） | `reference` + 提示词内否定句 | 见 ③ 与 ④ |

注意 `subject_reference` 目前**只有映射表登记，前端无任何地方产生它**（`generate-actions.ts:114` 只产 `first_frame`/`last_frame`/`reference`）——属"映射已备、写口未开"。

**路径 C（真·强度参数）**：**目前平台无承载**。若上游渠道（Seedance/ModelScope）支持权重类参数，需要在 `video_compat.py:504-526` 的 `_build_media_content` 里新增字段——但**本审计未在仓库中找到任何上游文档/配置证明该参数存在**，标为**【推测】**，不建议在无渠道证据时先做。
