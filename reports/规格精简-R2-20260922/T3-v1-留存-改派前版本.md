### 3.3 对「仍写错」的机理解释（与 §2 推力对应）

为什么模型会**推翻自己 3 秒前刚写好的合规草稿**？三处推力在同 step 内共同作用：

| 机理 | 对应推力 | 在推理中的痕迹 |
|---|---|---|
| **落盘句许可**（`必须落盘（规格「角色方向」字段…）`）| 推力③ | `L35`：`但角色方向这种方针级一两句可写` —— **「但」字即对冲点在起作用** |
| **「方针级」被扩张解释** | 推力③ | 模型把 `89` 字的名单+形象词判为「方针级一两句」→ **「一两句」被理解为「一两个条目」** |
| **Skill 措辞强度**（`一律主动询问`×2） | 推力② | 模型对用户 5 答中的 `cast`/`scene` 两答**必须给出交代**，规格是最近的可写载体 |
| **结构无约束** | 推力④ | 无任何依据阻止「名单独立成条」（条目 14→16） |

**★ 一个可验证的旁证**：模型在 `L36` 中**同时**写了合规草稿**和**（在草稿之前）与落盘句一致的表述——

```text
L36: 写入判据：…角色名单/场景清单属明细，应归故事板元素，不写规格——但角色方向这种方针级一两句可写
```

→ 它**先自我说服「可写」**，然后写出草稿；但**草稿实际是合规的**（因为草稿只用了 1 条且未列形象词）；**真正的违规发生在草稿之后的实参改写**。

**这一发现的方法论价值**：**「推理文本」与「工具实参」是两个可分离的观测面**。仅看推理会误判为「模型很守规」（推理中反复引用判据③、且草稿合规）；**必须对齐两者才能定位真因**。本报告建议终案采纳此方法。

```python
# 规格结构度量（2026-09-22 批R2，事故 9999/Q2）
# 依据：GOVERNANCE §二「能代码校验就下沉」+ «确定性三问»（标题数/条目数
# = 可算+可判+零创作空间 → 收归系统）。数值来源 = flova N=2 样本观测区间
# 上界（标题 1–2 / 条目 10–11），非条款（见 T11 §6.1 K′15）。
_SPEC_H2_MAX = 1          # 二级标题上限（对齐 06 样本的 1 个 `## 分集结构`）
_SPEC_ENTRY_MAX = 12      # 维度条目上限（区间上界 11 + 1 容差）


def spec_structure_metrics(text: str) -> Dict[str, int]:
    """规格文档结构度量（纯函数、无副作用、可单测）。

    返回 {h1, h2, entries, over}：
      h1/h2  = 一级/二级标题数
      entries= 无序条目数（`- ` 行首）
      over   = 超限项数（0 = 全部在限内）
    """
    s = str(text or "")
    h1 = len(re.findall(r"(?m)^# ", s))
    h2 = len(re.findall(r"(?m)^## ", s))
    entries = len(re.findall(r"(?m)^- ", s))
    over = (1 if h2 > _SPEC_H2_MAX else 0) + (1 if entries > _SPEC_ENTRY_MAX else 0)
    return {"h1": h1, "h2": h2, "entries": entries, "over": over}
```
