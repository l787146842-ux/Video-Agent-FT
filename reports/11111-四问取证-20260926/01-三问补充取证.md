## Q2 · 有 todo 工具，为什么还会假停

**结论：todo 与假停无关，且真正诱因是 harness 的"样板话回声"。**

### 2.1 todo 在本平台「只写不回读」——它对防早退零作用

| 环节 | 实现 | 结论 |
|---|---|---|
| 写入 | `todo_write` → `conversations[n]["todos"]` | 只写 |
| 回注模型 | **已整段删除**（2026-09-23 批13）：`prompt_builder.build_todo_note` / `_read_todos_from_raw` 均不存在 | **零回注** |
| 读取 | `read_session_todos` docstring 自认「当前**仅由测试消费**」 | 无生产消费方 |

依据原文（`prompt_builder.py:63-68`）：
> `_read_todos_from_raw` 与 `build_todo_note` 已**整段删除**（清单尾部注入退役）……
> 原版注释明写清单事件是 UI/replay 状态而非第二条模型消息

⇒ 子代理写完清单，**下一轮自己看不见**。所以「有 todo」≠「有进度锚」。

### 2.2 真诱因：harness 样板话回声（**这是 harness 的问题**）

**机制**（可复现证据链）：

1. 端点 400 拒收标准 `tool role` 消息 → 适配器降级为 user 伪装；
2. 降级时，模型**过去的** `assistant(tool_calls)` 消息被替换成样板话：
   `（本轮为工具调用轮：{工具名}，结果见紧随其后的系统消息）`
   （`openai_compat.py:329-334`）
3. **该降级是粘性的**——日志原文：「本实例后续请求**沿用旧通道**」；
4. 于是模型每一轮看到的自己的历史，**全是这句样板话**；
5. 模型开始**模仿**它。

**实测证据（11111 两次子代理）**：

| 会话 | seq | 正文 | 该步实际工具调用 |
|---|---|---|---|
| #1 | 81 | 样板话 | **无**（纯文本轮 → 判假停） |
| #2 | 57 | 样板话 | 有（5 个，正常轮） |
| #2 | 66 | 样板话 | **无**（纯文本轮 → 判假停） |
| #2 | 76 | 样板话 | **无**（纯文本轮 → 判假停） |
| #2 | 87 | 样板话 | **无**（纯文本轮 → 判假停） |

**关键判别**：harness 生成式是**逗号连接**（`", ".join`），**从不产 `×N`**；
而实测正文含 `×4` / `×5` / `含 corrected 字段顺序` —— 这些是**模型自己加的**。

⇒ **harness 给了前半句模板，模型照抄并自行补全**。seq=57 那轮尤其实锤：
该轮**确实有 5 个工具调用**，正文却仍是样板话——说明它已把这句当成"说话习惯"。

**危害**：模型被告知「正文见系统消息」后，倾向于**只写正文、忘记发工具**，
于是被判假停。模型自己的推理两次自认（`sb2.ev.txt`）：
> `I again failed to emit tool calls.`（step 7）
> `I need to actually call the tools now. My previous response apparently didn't include tool calls`（step 5）

**配额账**（即"配额耗尽"）：`FAKESTOP_AUTO_RESUME_MAX = 2`
（子代理#1 step3/step8、子代理#2 step4/step6、主代理 step1/step3，均 2/2 用尽后放弃）。
**R4 已修**：耗尽后未打卡 → `incomplete`，不再冒报 completed。

**归属**：**harness 层**（适配器降级策略 + 粘性通道），非模型、非 Skill。
**建议修复方向**（待裁决）：降级时不要用「本轮为工具调用轮」这种**第一人称可模仿**的样板话，
改用系统口吻的标记（如 `[已省略的工具调用记录]`），且不写成完整句。

## Q3.2 · 是什么引导模型写「引用：」行

**结论：Skill 只要求"引用"，是模型自己选择了"尾部汇总行"这种写法。**

### 3.2.1 Skill 原文（唯一相关处）

`SKILL.md:77-78`：
```
- 每个 shot 描述必须包含：
  - **场景**：引用对应 element scene ID
```
⇒ 要求「**必须包含**」「**引用**对应场景」，**但没规定写成什么形式**。

### 3.2.2 全 16 个 Skill 里没有「引用：」这种行模板

`grep "引用：" data/skills/**/SKILL.md` 仅 2 处命中，均**与分镜 desc 无关**：
- `宣言式概念短片:49`「历史与流行文化引用」（文案内容）
- `未来科幻真人电影:123`「人物／场景引用：`<<<image_1>>>`」（视频提示词字段）

⇒ **平台和 Skill 都从未示范过「尾部写 引用：[A]、[B]」这种行**。

### 3.2.3 模型两种写法都用了（说明它知道正确的写法）

| 镜 | 正文内联令牌 | 尾部「引用：」行 |
|---|---|---|
| 0–3 | ✅ 有 | ❌ 无 |
| 4–8 | **❌ 无** | ✅ 有（且是**唯一来源**） |

模型推理原文（`sb2.ev.txt:54`）：
> `Careful: desc must not have trailing 引用. Tokens inline.`

⇒ **它知道规矩**（平台契约明写「禁止在 desc 尾部追加…汇总行」），
0–3 镜也照做了；**4–8 镜改回旧写法**，属执行不一致。

### 3.2.4 对裁决有用的事实

用生产函数 `ops.merge_shot_refs` 对 9 镜复算（删掉尾部行后重算引用）：

```
删除尾部「引用：」行后，全片共丢失引用 0 条
```

⇒ 该行**功能上完全冗余**（裸名提及自动兜住），删掉不丢引用。
且**当前无任何执法**（`prompt_gate` 只校验 `prompt` 字段，不读 `desc`）。

## Q3.3 · 是不是 harness 的问题

**分两半：引用这件事不是；但「模型看不见自己的工具调用」是。**

### 3.3.1 不是 harness 问题的部分

| 检查项 | 结果 | 证据 |
|---|---|---|
| 引用绑定生效了吗 | **生效** | 9/9 镜 shotRefs 非空、共 20 条正确落库 |
| 尾部行是唯一来源吗 | **否** | 复算丢 0 条 |
| Skill 引导了尾部行吗 | **没有** | 16 个 Skill 零处该格式 |
| 契约禁止了尾部行吗 | 有（且模型可见） | 2026-09-26 15:20 入库，服务 15:34 启动 |
| 契约有执法吗 | **无** | `fc_gates.prompt_gate` 不读 `desc` |

⇒ 「写不写尾部行」是**模型的表达不一致**：平台既没禁成功（无执法），也没受损失（绑定照样成立）。

### 3.3.2 是 harness 问题的部分（两处）

**（a）样板话回声致假停** —— 见 §2.2，已取证，**harness 层**。

**（b）子代理回给父代理的"摘要"= 样板话**

两个子代理的最后一条 `assistant/message`（即父代理收到的回摘要）逐字是：
```
（本轮为工具调用轮：storyboard_create_group ×5，结果见紧随其后的系统消息）
```
零信息量。依据：`round_end_policies.py:500-503` 对子代理
`accumulate_visible(..., last_only=True)` **取末条**，而末条恰是样板话。

⇒ 父代理收不到真实汇报，只能自己 `read_state_group` 复查
（`conv-main` step6 推理：「看起来子代理只完成了部分工作」）。**harness 层**。

### 3.3.3 归属表

| 现象 | 归属 | 是否 harness |
|---|---|---|
| 后 5 镜写尾部「引用：」行 | 模型表达不一致 | **否** |
| 引用绑定生效 | 平台正常 | 否 |
| 契约无执法 | 平台设计选择（用户明令不加闸） | 否 |
| **样板话回声致假停** | **适配器降级策略（粘性 + 可模仿样板话）** | **是** |
| **子代理回摘要 = 样板话** | **摘要取末条** | **是** |
