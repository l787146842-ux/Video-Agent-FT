### 1.4 坏串从哪里来：模型猜了形态，平台静默 str() 掉

会话转录 `.jsonl` 里模型自己的原话（`conv-1790770354-2a25751a.jsonl`）：

> "Now refAssets format — uncertain. … let me do a first single call to test. I'll use refAssets as an array of objects? … likely array of image URLs or array of {id, name, url, type}. … Let me just try objects with url+type+name — the richest."

落库后模型自己发现并被误导（seq 34）：

> "refAssets got stringified — each entry became a string of a dict. That's ugly. … The stored value shows strings in a list — the stored JSON literally has strings. **So the underlying storage converted my dicts to strings. That means the schema likely is List[str].**"

**代码侧确认**：

- 契约是**字符串列表**，`List[str]` **接受**任何字符串，故 pydantic 不拒收、闸机不报警：
  `src/video_agent/state/models.py:76` → `ref_assets: List[str] = Field(alias="refAssets", default_factory=list)`
- 静默 str() 的唯一现场 = `src/video_agent/state/storyboard_ops.py:533`
  ```python
  for raw in refs:
      item = str(raw or "").strip()      # ← dict 在此被 str() 成 Python repr
  ```
  且分支 ③ 明确「原样保留」（`:540-541`），坏串从此**永久留在状态里**：
  ```python
  else:
      value = item  # ③ URL / 未知：原样保留
  ```
- 而模型**没有任何形态契约可依**：`_DRAFT_FIELDS_HINT`（`src/video_agent/tools/storyboard_tools.py:34-87`）把 `refAssets` 列进合法字段名，但**通篇没有一句说明它是「媒体 URL 列表」** —— 对比同段对 `audioType`/`mediaType`/归属语义都写了长段正面契约。模型只能猜。

> 复算确认幂等死锁：`normalize_ref_assets(state, refAssets)` 再跑一次结果**完全相同**（`幂等？ True`）——坏串既不是草稿 id、也不是 URL，永远落分支 ③。

### 1.5 提示词产物差异：模板零差异，差异在"实例化"

**首要更正**：本地 skill 不是 Flova skill 的改写/精简版。实测字节级比对：

```

```

两侧唯一的差别是**标题行**：Flova 写 `（ImageToImage / GPT Image 2）`，本地写成「由全局设置决定」。**模板正文 21 行一个字符都没动。**

因此「我们的模板 vs Flova 的模板」这条对比轴**不成立**；模型写的 S3 提示词是**对同一份模板的忠实逐字实例化**（把 `\[Shot ID\]`→`S3`、`\[角色代号\]`→`曹彬` 等占位符填了值）。真正的差异是：**同一份模板，Flova 的模型把产物重写了，本平台的模型照抄了。**

Flova 实际提示词里那些"更好的写法"，**在它自己的模板里一处都没有**（`Panel N —`、`时长: 0-6s`、`pure black line art`、`thin black border`、`LEGEND BOX (top of sheet)`、`Chinese annotation block`、`16:9 landscape` 在模板中均不存在）。这是 Flova 模型的自发改写，不是模板给的规范 —— 也就是说，**"照抄 Flova 的实际提示词"≠"照抄 Flova 的现行模板"**。

## 2. 问题 2：参考素材栏图块不能加载

### 2.1 观测现象 → 机制映射

用户截图：4 个图块，每块「图裂图标 + 文字 `参考素材 1`…`参考素材 4`」。

**这块文字不是文件名，是 `<img>` 的 alt 文本**——`RefAssetBar.tsx:148-152`：

```tsx
<img
  src={safeUrl(url)}          // ← dict 字符串被 safeUrl 拦成空串
  alt={`参考素材 ${idx() + 1}`} // ← 图裂时浏览器显示这行 alt
  class="ref-thumb"
/>
```

### 2.2 `refAssetName()` 复算：33 字符恰好越过 32 阈值，回落到 `参考素材N`

`src/web/lib/prompt-ref-utils.ts:46-48`：

```ts
const fname = url.split('/').pop()?.split('?')[0]?.split('#')[0];
if (fname && fname.length <= 32) return fname;
return `参考素材${idx + 1}`;
```

对 S3 首条 dict 字符串逐字复算：

```
输入             = {'type': 'image', 'name': '设定图·曹彬', 'url': '/workspace/assets/gen-...png'}
split('/').pop() = "gen-1790576054-9122ee95fafa.png'}"     ← 尾部带着 '} 
长度             = 33
length <= 32 ?   = False                                   ← 恰好越过阈值
→ 返回 fallback  `参考素材1`
```

对照真实 URL：`gen-1790576054-9122ee95fafa.png` 长度 **31** ≤ 32 ⇒ 会正常显示文件名。**33 vs 31 这两个字符之差**就是「显示参考素材N」与「显示文件名」的分界。

### 2.3 右侧计数 `8` 的算术

`RefAssetBar.tsx:48-66` 的 `refCounts()`：

```ts
for (const url of props.refAssets()) {          // ① 4 条坏串 → refAssetType 判 'image' → +4
  counts[refAssetType(url, state.keyElements)] += 1;
  seen.add(url);                                 //    seen 里存的是坏串
}
const prompt = props.rec()?.draft.prompt || '';
if (prompt.includes('@') || prompt.includes('＠') || prompt.includes('<<<')) {
  const map = storyboardMediaMap();
  for (const [name] of mentionNamesIn(prompt)) {  // ② @曹彬 @程心 @AA @星环号球形舱 = 4 个
    const info = map[name];
    if (!info || seen.has(info.url)) continue;    //    info.url 是真 URL，seen 里只有坏串
    seen.add(info.url);                           //    ⇒ 永不命中，无法去重
    counts[info.kind] += 1;                       //    → 再 +4
  }
}
```

**4（坏 refAssets）+ 4（`@` 提及，去重失效）= 8**，与截图完全一致。
