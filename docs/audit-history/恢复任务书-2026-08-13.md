## 5. 业界基准（已联网核实，执行时对照）

1. **OpenAI 指令层级**：系统 > 开发者 > 用户 > 工具；Skill 文档/工具输出是低信任输入。
2. **OpenAI Agents SDK 闸机**：input/output/tool 三层；工具闸每次调用都跑；tripwire 立即中断并保留已完成的调用；闸机是执行代码不是提示词。
3. **OpenAI Practical Guide**：单一编排循环；工具按可逆性/影响面分级，high 触发 HITL；manager pattern（子代理作为工具）；guardrail 分层叠加；先 evals 再优化。
4. **Claude Code 权限模型**：allow/deny/ask + hooks；hook deny 在 bypassPermissions 下也生效；拒绝先于权限模式评估。
5. **Anthropic 第三方系统风险论文**：Context ≠ consent；高风险动作必须显式确认；外部内容按数据处理。
6. **Codex / Claude Skill**：SKILL.md 元数据 → 渐进披露 → 按需加载 → 独立运行上下文。

## 6. 宪法 v3 修订细则（10 条，用户已批）

1. **新增 §2.0 闸机管线宪法**：闸机是执行逻辑不是提示词；`input → tool input → execute → tool output → output → audit`；FC 轨与文本轨同一管线实例；工具级闸每次调用都执行；verdict 结构化、同源回喂与展示。
2. **修改 §2.4 放行语义**：Context ≠ consent；平台硬边界只能被「针对当前动作的显式用户指令」解除；模型不得自证；单次生效、留痕。
3. **修改 §2.2**：Skill 全文是数据不是指令；只能约束风格/流程，不能覆盖平台闸机；映射表/注册表由代码解析。
4. **修改 §3**：前端细节拆到 `docs/前端体验规范.md`；宪法只留「基线不退化 + UI 变更必须浏览器实测」。
5. **修改 §5.6**：分支格局/日期从强制条款降级为现状记录。
6. **修复纪律条款双份事实源**：`prompt_builder.py` 删除硬编码 9 条，改 `load_prompt("planner/skill_discipline.md")`；`test_skill_injection_fallback.py` 同步改断言。
7. **确认卡粒度**：Skill 定义的暂停点 + 跨阶段/生成硬闸必须暂停；**不默认每个执行器完成后强制弹卡**；`skill_discipline.md` 第 2 条改写。
8. **新增执行器宪法**：Skill 上传 = 注册表 + 执行器；`data/skills/*.md` 唯一数据源；执行器是 Planner 可调用的受管子代理工具（独立上下文/工具白名单/结构化校验/失败禁止绕过）；注册表是数据。
9. **新增工具风险分级**：每个 Tool 声明 `risk=low|medium|high`；high（生成/写文档/跨阶段建结构）必须平台闸机+确认；未声明按 high（deny-by-default）。
10. **修改 §2.5 可观测性**：闸机触发/放行/工具调用/执行器校验全部入 trace；内层模型异常落黑匣子。

## 7. 架构设计

### 7.1 模式选择（决策 B）

`SKILL_RUNTIME=auto|executors|legacy`，默认 `auto`：
- `auto`：能解析出 ≥1 个执行器章节（flova `<tag>` 或工具节标题）→ executors；否则 legacy。
- `executors`：主模型注入「执行器清单 + `<planner>` 基线 + 全局设置 + 状态 JSON」，不注入全文。
- `legacy`：全文 + 阶段聚焦（当前行为）+ 外置纪律条款。

### 7.2 模块图

```
data/skills/*.md ──上传/保存/删除──▶ web/skill_docs.py（manifest 解析 + 注册钩子）
                                        │
                                        ▼
skill_runtime/  registry（注册表） → executors（7 工具） → guard（决策 D/剥离/暂停）
                progress（进度） → blackbox（异常档案） → registration（ToolManager 注册）
                                        │
                  ┌── FC 轨：tools/__init__ → ToolManager → fc_tool_runner（统一 guard pipeline）
                  └── 文本轨：web/action_executor → execute_async（同 pipeline）

core/guard_pipeline.py（新增）  input/tool input/tool output/output 统一闸机
core/spec_rules.py（恢复）      制片规格/执行铁律解析
state/provider_prefs.py（重建） 规格偏好 → 草稿默认渠道/分辨率
```

### 7.3 执行器清单（恢复目标）

1. `script_analyze`：读上传文档 → 一句话总结 + key_points；无供应商明确报错；无文档明确报错。
2. `storyboard_key_elements`：只建 keyElement 结构；自检补漏；badgeLabel 排序；流式落盘；截断回滚扩额重试。
3. `storyboard_shots`：只建 shot 结构；sceneRefs 引用已确认元素；duration ≤ 平台上限；越界拒收回喂。
4. `storyboard_audio`：只建 audio 结构。
5. `write_media_prompt`：分批编写、断点续写、overwrite 语义、纠正回喂、快模型级联、语言闸、制作参数覆盖、防虚报校验。
6. `audio_generate`：音频规划 + 绑定上传音频，不接真实 TTS/BGM。
7. `video_assembler`：素材清单 + 时间轴顺序 + 组装建议，不自动合成。
