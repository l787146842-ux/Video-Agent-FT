## 二、逐维度审核详情

### 2.1 架构：四次范式收敛后的健康骨架

ADR 0001-0004 记录了本项目四次连续的范式收敛，路径清晰且每次都有退役教训归档：

- **ADR-0001（双轨 → 单轨）**：确立 FC 单轨，文本通道退居 mock/演示；
- **ADR-0002（控制流统一）**：消除散落编排，控制流归一；
- **ADR-0003（Workflow Runtime）**：runtime 定位为账本 + 客观探针 + 裁判的数据层，而非代模型行动的编排器；对标依据经修正挂 Temporal Durable Execution / LangGraph persistence（不可查证的 Flova Runtime Contract 已于前批移除）；
- **ADR-0004（主体回归）**：模型永远是唯一行动主体——runtime 机械直跑/审批直跑废除，顺序保障改「刹车」（stage_precondition 闸首位否决），暂停卡唯一发行主体 = 模型 `workflow_pause`，单一活跃暂停槽位互斥。

此收敛与 Harness Engineering 业界共识（单一 ReAct 循环 + 模型唯一决策点）完全一致。

**唯一结构性问题**：层级体量倒挂与大文件红线——

| 问题 | 数据 |
|---|---|
| web 层倒挂 core | web 47 文件 11,332 行 > core；`docs/action_executor下沉计划.md` 已立两阶段下沉路线（下沉前对外行为冻结禁改） |
| 6 个 850+ 行大文件顶满行数红线 | `web/generation.py`(974)、`core/planner.py`(916)、`core/fc_tool_runner.py`(910)、`web/action_executor.py`(885)、`skill_runtime/exec_common.py`(867)、`core/prompt_gates.py`(865) |

大文件拆分列为 P5（先减噪再动结构，见第四节路线图）。

### 2.2 指令体系：不混乱，仅两处死指针 + 一处漂移面

实测 `prompts/` 全量仅 217 行，`{{include}}` 组件化组装，P1 单一事实源纪律落实——指令密度与可维护性优于多数对标对象（Claude Code 的 CLAUDE.md 纪律「每行可追溯到真实失败」在本项目同样成立）。

问题仅三处：

1. **暂停纪律三层回声**：system / gate 文案 / 引导卡三层重复强调暂停纪律，合法但有措辞漂移面（P2 批次叙事折旧一并处理）；
2. **死指针一**：`ARCHITECTURE_RULES.md` L10 指向 `docs/archive/recovery-sources-20260813/...`，路径不存在 → 改写为不指向具体路径的历史说明；
3. **死指针二**：`docs/GOVERNANCE.md` §13.10（L143 附近）指向 `docs/archive/debt-ledger.md`，文件不存在 → 补建台账 vs 删节改「已清偿关闭」，**需用户裁决**（决策点一）。

### 2.3 臃肿：病灶 = 治理沉积物，而非常驻设施

「AI 越弄越臃肿」的质疑经审核**不成立为结构问题**，成立为沉积物问题。`scripts/acceptance.py` GATES 表证实常驻门禁仅 9 个（contract/prompt_budget/file_lines/func_imports/governance_refs/category_keys/legacy_orchestration/scaffold_registry/executor_skill_drift），其余均为历史批次遗留：

| 沉积物类别 | 数量 | 处置方向（P2） |
|---|---|---|
| 一次性迁移/清理脚本未归档 | 8 个（`migrate_*.py`×4、`add_spec_gate.py`、`dedupe_draft_ids.py`、`clean_incident_refs.py`、`clean_temp_artifacts.py`） | 迁 `scripts/archive/`，只归档不删除 |
| 批次叙事注释（「批 N/整改」等） | 约 142 处 + 6 处 `audit-08xx` 引用 | 按宪法 §9 折旧：保留结论删过程 |
| 措辞耦合测试（`read_text` 源码断言型） | 36 个 | 三类处置：门禁等价覆盖→删测试保门禁；纯措辞断言→迁门禁或删除；真实结构契约→保留 |
| 疑似过期中间态文书 | 5 份（action_executor下沉计划/兼容层移除计划/scaffold-registry-draft/nonfc-measurement-memo/layer8-feedback-inventory） | 逐一裁决：完结→迁 audit-history；活跃→去 draft 给到期日 |
| 治理机器自身 | 约 1000 行 | 随折旧台账观察，不做新增 |

### 2.4 闸机：设计合理，非过度设计

`src/video_agent/core/prompt_gates.py` 构成的闸机子系统是全项目最强子系统之一：

- **17 条 policy-as-data** 规则注册表，声明式可审计；
- **deny-overrides 三层**判定（任一 deny 即否决），结构化 `GateVerdict` 输出留痕；
- **文案单源**（`prompts/gates/messages.md`），闸机话术不散落；
- 与 Claude Code PreToolUse hooks 的设计哲学同构——**「hooks guarantee behavior, prompts only suggest」**：行为保障靠机制否决，不靠提示词劝说。

结论：维持现状，仅按 `docs/脚手架折旧规程.md` 第五节执行折旧盘点（连续零触发降档软警告，安全类豁免）——对应 P2-6。

### 2.5 Workflow Runtime：账本扎实，映射启发式是短板

**扎实面**：runtime 账本（node_attempts/stage 状态）、客观探针（不依赖模型自报）、断点续跑，均符合 ADR-0003 定位。

**三个弱点**（P3-12 正对症）：

1. step→stage 映射靠 `_STEP_STAGE_HINTS` 关键词启发式（`src/video_agent/core/pipeline_orchestrator.py` L160-186），脆弱且不可声明；
2. sidecar schema 弱（`sidecar.py` L66-93 手写校验，无 dataclass 约束）；
3. `step_done_conditions` 在 sidecar 中声明了但**全库无消费方**——声明即债务。

### 2.6 Skill Runtime：同构 Claude Agent Skills 且声明化更高，表达力受限

**优势**：progressive disclosure 三级披露（元数据 → 章节摘要 → 按需注入全文）与 Claude Agent Skills 标准同构，且以 sidecar JSON 声明化实现，优于 Flova 的纯散文式 skill。

**弱点**：

1. 表达力受限于 `skill_runtime/registry.py` `TOOL_STAGES` 的 7 章节固定词汇表——访谈/MV/纪录片类 skill 被迫套模板；
2. 非管线类 skill 退化为全文直注（`src/video_agent/core/prompt_builder.py` L295-342），token 效率失守；
3. legacy 路径同章节重复注入（`prompt_builder.py` L440-465，纯 token 浪费，P3-17 合并）。

P3-15 方案：sidecar 声明 `custom_sections` 开「自定义章节 → 通用执行器」通道；`scan_skills.py` 先增一致性诊断探针（诊断先行再升门禁）。

### 2.7 上下文治理：对齐三杠杆其二，缺最安全的一杆

已对齐 Anthropic 上下文三杠杆中的两杆：**compaction**（`prompts/planner/session_compact.md`）与**轮组原子截断** + **前缀缓存排序**（prompt_builder 段落排序为前缀缓存服务，对齐 Codex）。

欠账四项（P3-14 逐项对症）：

| 欠账 | 位置 | 对策 |
|---|---|---|
| 缺 tool-result 消化（Anthropic 明示最安全杠杆） | 历史中超阈值 FC 工具结果原文常驻 | 「摘要 + 状态已在工作台 JSON」指针化；只消化已投影结果，保留最近 2 轮，`TOOL_RESULT_DIGEST_CHARS=0` 一键关 |
| compaction 按条数而非 token 触发 | `src/video_agent/web/chat_consume.py` L65-86（12 条阈值） | token 驱动（>0.6×窗口）或条数双条件；模板补「未决事项 + 最近关键产物名」对齐 Codex handoff |
| 记忆召回 query 无扩展 | `src/video_agent/core/prompt_builder.py` L467-480（仅最近一条用户消息） | 扩为「用户消息 + 当前阶段标签 + 激活 Skill 名」 |
| fallback 分词单字切分近乎失效 | 记忆检索降级路径 | 改 bigram |

### 2.8 Agent 交互体验（重中之重）：透明度登顶，控制点缺两类

**过程透明度达业界最高水准区间**，`docs/前端体验规范.md` 17 条逐条落实且有测试钉死：

- 思考外显、工具操作账目（StageCard 归 AgentTimeline 单家呈现）；
- 刷新后时间线重建（SSE 断连非数据丢失）；
- 轮级 regenerate（任意 agent 回复可机械重跑，不重写历史）；
- 审批向导（affordances 纯函数 `deriveAffordances` 单源派生，vitest 12 例钉死）；
- 排队引导与停止语义。

**差距清单**（P4 对症）：

1. 用户控制点七类缺两类：**编辑**（用户气泡回填重发，本期零后端降级方案）与**继续**（停止后经 suggested_actions 下发「继续刚才的任务」，不改 SSE 协议）；
2. 工具条目 `result_summary` 不可展开（数据面已备，纯前端补齐）；
3. 对标 Flova 的最大产品级差距：**多版本对比挑选 + 选择写入上下文 + 选定版本续跑**——属产品级新能力，列 P5/另立项。

## 三、业界对标结论

### 3.1 Codex

- 单一 ReAct 循环、FC 唯一动作通道、AGENTS.md 32KiB 硬上限、handoff-oriented compaction、段落排序为前缀缓存服务；
- **本项目已对齐**：ADR-0001 单轨、prompt_builder 前缀缓存排序、session_compact 模板。欠账：compaction 触发改 token 驱动、模板补 handoff 四段式要素。

### 3.2 Claude Code / Anthropic

- 515 个条件组装组件、「hooks guarantee behavior, prompts only suggest」、CLAUDE.md 短小纪律（每行可追溯到真实失败）、Agent Skills 三级 progressive disclosure、上下文三杠杆（compaction / structured notes / sub-agent，其中 **tool result clearing 为最安全杠杆**）；
- **本项目已对齐**：指令组件化与短小纪律、闸机机制化否决、Skill 三级披露。欠账：tool-result 消化未实现（P3-14a）。

### 3.3 DeepSeek Harness

- 一切皆插件：模型/工具/技能/审批均为 waterfall 插件链；
- **本项目同构**：AdapterFactory 声明式注册 + 闸机前置否决。**更进一步处**：本项目 sidecar DAG 声明外置为数据（而非插件代码），可审计性与可维护性更高——故「推翻 sidecar 改纯代码 DAG」的替代方案被否决。

### 3.4 Flova（同域直接竞品）

- 布局同构：左故事板 / 右 Agent / 中画布；
- **核心差异（最大产品级差距）**：素材/分镜级多版本对比挑选 + 选择行为写入项目上下文（「你的判断会被记住」）+ 规划在选定版本续跑。列 P5-27 另立项。

### 3.5 Harness Engineering 共识：棘轮与折旧双纪律

- **棘轮纪律**：只在真实失败后加约束（本仓库 `docs/archive/incident-ledger.md` 教训归档制与之同构）；
- **折旧纪律**：模型变强后不再承重的组件应拆除。
- **本项目现状**：棘轮半程极好（门禁/预算/白名单/黄金语料全部机械化运转）；**折旧半程滞后**（沉积物见 2.3）——这正是 P2 立项依据，也是「AI 越弄越臃肿」风险的制度化答案。
