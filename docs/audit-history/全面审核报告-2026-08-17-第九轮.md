## 三、头号发现（P0）：模型 fallback 链 NameError

**位置**：`src/video_agent/web/chat_service.py` L495

```python
# L483：只解包了 model
next_model = candidates[idx + 1][1]
...
# L495：next_provider 从未定义（全仓库仅此一处引用）
AgentTracer.get_instance().record_fallback(next_provider, next_model)
```

**性质**：`NameError: name 'next_provider' is not defined`，在 except 分支内必抛，Python 静态检查（tsc 类比）不覆盖、运行时才会触发。

**触发条件**（四项同时成立，且恰是产品推荐配置）：
1. `model_fallback_enabled` 开启（宪法 §4，默认开）；
2. 主模型遇瞬时故障（5xx/超时/连接失败，`retryable=True`）；
3. 本轮尚未执行任何操作（`applied_seen=False`，否则本来就不该 fallback）；
4. 候选链长度 >1（多供应商配置了同一聊天模型——产品推荐的多渠道冗余配置）。

**双路径症状**（已坐实两条消费路径）：
- **任务式路径**（主前端 use-sse.ts → startAgentTask）：`_run_agent_task` L226 的 `except Exception` 兜底捕获后 emit SSE_ERROR。用户先看到状态条「模型已切换重试…」，紧接着收到内部错误外泄气泡「服务端异常： name 'next_provider' is not defined」。**fallback 完全失效，且错误文案向用户暴露实现细节**。
- **SSE 直连路径**（`/agent/chat/stream`，src/web/api/sse.ts L23 有调用）：stream_worker 仅 try/finally 释放请求槽，sse_event_generator（sse.py）只查 task.done()、无 task 异常监控。worker 静默死亡后队列再无终态事件，**前端永远卡在「已切换重试…」状态条直到断连超时**。

**测试盲区证据**（三条相关测试全部绕过生产路径）：
- `test_nine_fixes.py` 直调 `tm._apply_event` 构造 fallback 事件；
- `test_b10_metrics.py` 直调 `tracer.record_fallback("provB","m1")`；
- `test_config_fallback_switch.py` 只测开关字段。
- → `_real_stream` 的 fallback except 分支**零覆盖**。

**修复建议**（本轮不动手，整改批次待用户裁决）：
1. L483 改为 `next_provider, next_model = candidates[idx + 1]`（与 `_fallback_switch_payload` 的语义对齐）；
2. 补 fallback 路径集成测试：mock 主候选抛 retryable AdapterError，断言次候选被调用 + `model_fallback` 事件下发 + `record_fallback` 参数正确；按 G4 同类全覆盖原则，任务式与 SSE 直连双路径各一例。
