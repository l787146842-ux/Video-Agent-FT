## B1 · P0：fallback 链修复 + 路径级测试立法

**归属层**：web/chat_service（修复）+ tests/integration（测试）。
**原则**：先写测试并在未修复代码上确认红灯（NameError 复现），再修复转绿——「先红后绿」是验证测试真实覆盖生产路径的仪式，防再出「测试全绿但路径零覆盖」盲区。

### 改动点
1. `chat_service.py` L483：
   ```python
   next_model = candidates[idx + 1][1]
   ```
   改为：
   ```python
   next_provider, next_model = candidates[idx + 1]
   ```
   （与 `_fallback_switch_payload` 同语义；L495 调用点不动。）

### 新测试 `tests/integration/test_chat_fallback_chain.py`（约 80 行）
mock 装配参考既有 `tests/mock_adapters/` 与 `test_nine_fixes.py` 的 StateManager/emit 收集器模式：

| 用例 | 路径 | 断言 |
|---|---|---|
| 1. 任务式 fallback | `_run_agent_task` → `_stream_worker_impl` → `_real_stream` | 主候选 mock 抛 retryable AdapterError（5xx）→ 次候选 adapter 被创建并完成；事件序列含 `model_fallback`（provider=次候选，B0/F4 语义）+ 终态 `done`；无 SSE_ERROR 气泡；tracer `record_fallback` 记录参数 = (次候选 provider, model) |
| 2. SSE 直连 fallback | `stream_worker` + `sse_event_generator` | 同上故障注入 → 事件流含 model_fallback + done，队列有终态（无静默卡死） |
| 3. 防回退（参数对账） | 同用例 1 | 断言 `record_fallback` 收到的 provider 是**次候选**而非失败方（正是 L495 错位的语义点） |

**不新增 acceptance GATES 行**：fallback 遥测对账（P2-2）由用例 1/3 的 pytest 断言承载，pytest 已在 acceptance SUITES 内。

### 验收
- [ ] 未修复代码上新测试红灯（NameError 复现）
- [ ] 修复后 pytest 全绿（1106+新增）
