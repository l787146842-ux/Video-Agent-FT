## 4. 批 4 — ⭐主体回归：直跑语义正名（P3a，用户 2026-08-21 质疑后升级，待裁决）

**背景（说法）**：直跑原义 = 用户授权模型连续执行不暂停（autonomy）；0818→0820（ADR-0003）
渐变为 runtime 机械直跑、主模型不参与启动。业界核实（Codex --full-auto / Claude Code
auto mode / DeepSeek Harness 审批插件 / Anthropic workflow 每节点仍是 LLM 调用）共识：
确定性 = 把关模型发起的动作，不是系统代替模型发起动作；「不暂停」是用户授予模型的
权限档。「hooks guarantee behavior」的真实含义是钩子保证模型行为边界，非代替模型行动。

**裁决提案（ADR-0005 主体回归，待用户审定）**：
1. 废除 runtime 自主行动能力：轮始不再自动执行执行器；每轮由模型接到用户消息后
   发起工具调用。带附件首条消息由模型接手（读后调 script_analyze），系统不静默自动分析。
2. 顺序保障保留但改执行模式：阶段表/依赖图/stage_precondition 闸全部保留，
   全部体现为工具执行路径首位闸（模型越阶即拒收回喂）。防越阶靠刹车，不没收方向盘。
3. 「不暂停」恢复为自主性档位：用户指令或开关授予模型豁免权，非平台硬暂停点
   （生成/写文档/跨阶段建结构）模型可不发 workflow_pause；硬闸任何档位必暂停。
4. 暂停卡唯一发行人 = 模型 workflow_pause（对齐 AskUserQuestion）；runtime 失去发卡权；
   系统派生选项面/层 9 兜底引导卡/单一活跃暂停槽位（pause_active 互斥，重发拒收留痕）保留。
5. 性能解法 = 不让模型猜（客观状态 + Skill 声明下一步 + 系统建议直达上下文，
   阶段过渡目标 1 轮 1 次工具调用），而非不让模型参与。
6. 机械卡/合成动作条目退役：时间线每条目对应真实发生的动作。

**影响**：ADR-0003 基线测试（test_workflow_runtime_1111 / workflow_1111_baseline.json）
按新语义重写；`drive_turn` 直跑分支退役（check_legacy_orchestration 登记防复活）；
ADR-0003 的 Flova 行清理并入本批或批 1。风险：顺序漂移回归（三层闸兜底）、
性能需重测（目标：阶段过渡 ≤1 规划轮）。

**验收**：新黄金轮次契约（模型主体 + 闸兜底）；双暂停负面用例（槽位互斥拒收留痕）；
skill_pause_golden 快照按新发卡主体重锁；acceptance 全 PASS。

## 5. 批 5 — 自主性档位与平台硬闸（P3b，依赖批 4）

**目标**：「连续执行不暂停」成为用户可控的授权档位；平台硬闸不依赖模型自觉。

1. 新增自主性档位（autonomy level）：默认档 = Skill 暂停点必停；连续档 = 用户指令
   （「继续不用停」）或顶栏开关授予，模型豁免非硬暂停点。档位即时消费规则、
   留痕（可追溯到授予它的用户消息/开关状态，Context ≠ Consent）。
2. 平台硬闸（§2.1 platform.*：生成确认、写文档、跨阶段建结构）在任何档位下
   经 guard_pipeline 内嵌执行路径强制暂停（hooks guarantee behavior，fail-closed）。
3. `validate_sidecar` 注册期门禁：Skill 声明的暂停点只可加严不可削弱平台硬闸（§2.2 不变量复用）。

**验收**：单测（默认档暂停点必停 / 连续档豁免非硬暂停 / 硬闸任何档位拦截）；
授权留痕断言；acceptance 全 PASS。
