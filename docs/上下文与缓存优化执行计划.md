### 批 A · reasoning_content 回传 400 兜底（保所有模型可用）

现状：`openai_compat.py` 的 400 兼容探针 `_strip_unsupported_on_400`（~L309-324）只剥 payload 顶层可选字段（`response_format` / `reasoning_effort`），**不覆盖 assistant 消息内的 `reasoning_content`**。换一个拒收思考回传的模型/中转会持续 400。

**改动**（`src/video_agent/adapters/openai_compat.py`）：
1. `_strip_unsupported_on_400` 新增分支：400 报文点名 `reasoning_content`（`data.field` 或 body 含该串）时，遍历 `payload["messages"]` 剥离 assistant 消息的 `reasoning_content` 字段 → 记入 `self._unsupported_fields`（键 `messages.reasoning_content`）→ 返回 True 触发重试一次。
2. 请求组装处（`_gate_reasoning_passthrough` 调用点，~L224-239 / L344-352 / L474-480）：若 `messages.reasoning_content` 已在记忆集合，则该请求直接走剥离路径（同实例不再试探）。
3. `record_degradation` 埋点照现有惯例。

**测试**：`tests/unit/` 现有 openai_compat 400 兜底测试文件（grep `_strip_unsupported_on_400` 定位）补三例：点名剥离重试成功、二次请求不再携带、未点名不误剥顶层字段。
**验收**：`python scripts/acceptance.py --quick` 退出码 0。

### 批 B1 · read_skill 回喂去重（说明书双份治理）

**改动**（`src/video_agent/core/fc_feedback.py` `format_tool_results`，~L205-270；调用方 `turn_executor.py` ~L446-461 传入 messages）：

2. 回喂行格式保证可扫描（现有 marker 行已含工具名与参数摘要，验证后复用；不足则在该行补结构化后缀）。

**测试**：`tests/unit/test_fc_tool_feedback.py` 补：无 section 指针化、同 section 二次指针化、不同 section 全文照旧。

### 批 C2 · 工具结果切换标准 tool role（对齐 Codex/DSH 格式）

现状：工具结果伪装 user 消息回喂（`turn_executor.py` ~L446-461 `format_tool_results`）+ assistant 文本占位（`agent_loop.py` ~L548-564）+ user「第 N 轮已执行请继续」（~L565-571）；fc_feedback 全家族靠文本前缀 `FEEDBACK_MARKER` 识别 user 回喂消息。

**改动**：
1. `turn_executor.py`：每个工具调用产出一条 `{"role": "tool", "tool_call_id": <C1 透传的 id>, "content": <现有文本格式>}`（content 维持现有行式文本，消化/压缩的文本解析复用）；`view_storyboard_media` 的图片结果**保留 user 多模态回喂**（tool role 不承载图片，业界同口径）。
2. `agent_loop.py`：assistant 占位从文本占位改为标准 `assistant.tool_calls` 消息（`content` 空 + `tool_calls: [{id, type:"function", function:{name, arguments}}]`，`llm_reasoning_passthrough` 开启时仍附 `reasoning_content`）；消息顺序 = assistant(tool_calls) → tool 结果（们）→ [图片 user 消息] → user STEP_FEEDBACK（OpenAI 语义天然合规）。
3. `fc_feedback.py`：`digest_projected_tool_results` / `compress_prior_feedback` / `strip_prior_feedback_images` 的角色判断从 `role=="user"` 扩展为 `role in ("user","tool")`；文本解析逻辑不变。
4. 纯文本保底通道（`supports_function_calling=False`）不产生 tool_calls → 保留旧 user 回喂路径，双路径并存。
5. 400 兜底：端点拒收 tool role（罕见）→ 按模型记忆回退 user 伪装（复用批 A 思路，`record_degradation` 留痕）。
6. `prompts/planner/feedback.md` 的 STEP_ASSISTANT_PLACEHOLDER 随占位改造评估退役（assistant.content 为空在 tool_calls 形态下合法，无需占位文案）；STEP_FEEDBACK 保留。

**测试**：`tests/unit/test_fc_tool_feedback.py`、`test_turn_executor.py`、`test_agent_loop.py`、`test_fc_tool_runner*`、`test_batch_checkpoint*` 等全家族回归（grep `format_tool_results` / `FEEDBACK_MARKER` 消费方逐一过）；新增：tool 消息形态断言、id 配对断言、保底通道不受影响断言、400 回退断言。
**验收**：--quick + 批末全量 + 5555 同场景真实项目冒烟（用户目测行为：模型不再出现「历史是否重复」式澄清思考）。
