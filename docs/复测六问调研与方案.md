## 主刀：会话层 append-only 化（抄 dsh，架构级）

- **事件流**：轮内 assistant(tool_calls) + tool 结果持久化进会话 JSONL（dsh：「已提交事件绝不重写」），每请求全量回放——读过的 Skill 章节/文档跨轮留存，重读消失（这是 dsh 与我们唯一的结构差异，也是 70K 增长、跨轮重读、缓存缺口三个问题的共同根源）。
- **修剪器**（抄 dsh `compaction-tool-result-pruner`，参数原样）：工具回喂超 **8192** 码点 → 头 **4096** + 中省略标注 + 尾 **1024**，零模型调用，原文留事件流可回放。
- **阈值压缩**（抄 dsh `compaction-basic`）：上下文到预算 **80%** 触发——最老平衡轮组换结构化摘要、逐字保留最新尾部，摘要请求复用热前缀 cache。（把退役的 LLM 摘要 compaction 以正确形态请回：阈值触发，不再每请求必触发。）

**改动面**：chat_service 会话存储演进（现有 chatMessages 按名义消息导入事件流）+ 装载链路 + 修剪器 + 阈值压缩。需先出细案（存储格式/迁移/触发参数）审定后动工。

**验收**：①trace 无同章节二次全文回喂；②cache_hit_report 稳态命中率实测（目标 ≥95%）；③上下文增长曲线平滑（修剪/压缩按阈值触发）。

## 拒因话术纯事实化（原则 2 的全局落实）

- 未知工具拒因：`工具 'X' 不存在。请核对可用工具清单后重试。`（主抄 dsh `unknown tool "X"`；删「疑似拼写错误」推断）。层级归位：解析层（闸机链之前）直接返回结构化错误，不经风险闸；风险闸未注册兜底保留为最后防线（fail-closed 不变）。
- **全局排查项**：过一遍全部回喂/拒因模板，清掉推断式表述。已发现一例：空响应兜底「上游**可能**瞬时抖动」——同批改为纯事实（如「这一步没有返回可见内容，回复『重试』可再次执行」）。

## 规格收集（用户裁决 2026-09-09：平台零规则）

- 平台协议**不加任何规则**（含撤回 v4 的「同一次分组收集」句）。分卡属模型/Skill 层面的执行节奏问题，对产物质量无影响；「什么都不加、什么都不管」= 与 dsh/Flova 形态完全一致，少一条规则少一个打架源。
- 既有机制保持原样：分组收集卡 + 分页向导 UI 载体不动，纪律 5 原文不动；模型怎么收集归模型 + Skill 正文。

## 思考打架的归属（补记）

打架来源三类，归属不同：①**规则冲突类**（回喂与纪律对冲、✓ 歧义）——上一批已修（探针退役、判定式收拢、进度计数化），不在本方案；②**状态断层类**（上轮动作/冻结调用下轮蒸发，模型每轮从状态 JSON 反推）——**本方案主刀的直接收益**：事件流全量回放后模型可见完整发生史，反推式梳理消失；③**指令体量类**——按治理靠人工审核控制，不在本方案。
