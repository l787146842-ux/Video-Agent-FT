# 脚手架折旧规程（正向设计改造 2-3）

> 业界依据：Anthropic《Effective Harnesses for Long-Running Agents》——
> "Every component in a harness encodes an assumption about what the model can't do
> on its own. These assumptions go stale as models improve. Strip away scaffolding
> that's no longer load-bearing. Test by removing one component at a time."
> 本规程把「拆除」制度化，与「新增」（宪法 13.5 Q0）构成闭环；
> 裁决口径承接 GOVERNANCE §13.14（治理频率与折旧裁决，到期必裁决）。

## 一、对象

`src/video_agent/core/scaffold_registry.py` 中 classification=scaffold 的条目
（存量清单已审定入账 registry，历史盘点见 git tag audit-history-archive-20260826 之 scaffold-registry-draft）。invariant 类不入本规程，
接受季度审计即可。

## 二、触发时机

1. **模型升级拆除仪式**：每次主模型/执行器模型切换后 1 周内执行一轮；
2. **季度脚手架审计**：与原「严禁审计」（宪法 13.6）同批执行；
3. **退役条件成熟**：条目 retest_policy 所述前置达成（如阶段 4 双轨退役）。

## 三、拆除仪式（逐件拆测，禁止批量）

对每条 scaffold 依次执行：

1. **关闭**：以特性开关或代码移除方式停用该组件（优先代码移除 + 备份分支，
   宪法 §5 血泪条款：开工先备份、每批即 commit）；
2. **复测**：跑该条目 evidence 指向的回归用例 + `python scripts/acceptance.py --with-eval`；
3. **判定（到期必裁决，GOVERNANCE §13.14(b)）**：每个登记项到复审期必须给出
   明确裁决并留痕，「证据不足」「暂缓」不是合法裁决结果：
   - 不劣化 → 裁决**下账**：永久删除组件代码，同批从 SCAFFOLDS 移除条目、
     下调 `SCAFFOLD_COUNT_BASELINE`、更新本规程附录台账一行；
   - 劣化 → 裁决**保留**：恢复组件，台账记「仍承重」+ 证据（eval 差异摘要），
     并钉死下一个复测时点（下一个模型周期）；
   - 证据不足以判定 → 同样裁决**保留**并钉死复测时点，附理由入台账，不得悬置。
4. **留痕**：拆除/保留结论记入本规程附录（未清偿残留项另登记于仓内清单 `docs/未清偿债务清单.md`），代码注释只写结论不写过程（宪法 §9）。

## 四、棘轮

- scaffold 计数只降不升（`scripts/check_scaffold_registry.py` 门禁强制）；
- 上调基线 = 新增脚手架，必须经 13.5（含 Q0）决策树 + 书面裁决，同批修改基线。

## 五、棘轮门禁折旧条款（审核整改批 7，2026-08-21）

防「治理机器自身成为臃肿源」：每个 check_* 棘轮门禁与每条运行时闸机规则
都是有维护成本的资产，必须有真实拦截价值才值得保留。

1. **盘点**：季度审计时运行 `python scripts/audit_gate_triggers.py`（只读、
   幂等）产出盘点表：运行时闸机按 trace 账本统计 rule_id × 判定/拦截/覆盖；
   触发计数遥测自动落盘（`data/gate_trigger_counts.jsonl`，闸机判定出口
   自动写入）并由本脚本汇总，不再人工补录；CI 棘轮门禁输出清单，
   触发情况由 CI 运行记录佐证；盘点表附「超期未裁决点名」节（治理瘦身
   第二批，任务#4）：观测窗/零触发降级候选（安全类豁免）、待裁决条目超期、
   脚手架季度审计义务——机器点名不代替裁决，裁决留痕仍在既有台账；
   遥测历史不足两季审计周期时如实标注「数据不足、暂不列入」，不虚构超期；
2. **退役条件声明（GOVERNANCE §13.14(c)）**：新增门禁脚本必须在脚本头部声明
   退役条件（触发场景消失即下账）；在 `scripts/acceptance.py` GATES 表登记时
   同步登记退役条件。无退役条件声明的门禁不得入账；
3. **折旧判定**：连续 N 轮（N=4 个审计周期）零触发/零拦截的门禁，
   **降级为软警告**（保留代码不删，退出码不再变红），并下账
   `scaffold_registry`；降级后若劣化回归再现，按原基线恢复棘轮；
   复审到期必须给出降档/保留/下账裁决（§13.14(b)，不得悬置）；
4. **例外**：安全类闸机（平台硬边界/画布边界/密钥边界）不参与折旧，
   零触发是常态而非折旧信号；
5. **边界**：本条款只处置「触发计数」维度的折旧；语义正确性审计
   仍归黄金语料校准（§2.6）与拆除仪式（第三节）。
