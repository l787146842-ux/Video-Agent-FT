### 关于你发现的文案 bug（核实成立）

`ExecutionPreferenceSection.tsx:58` 印着：

> "任何档位下：未注册工具、文档写入与画布操作等高危动作照常拦截，**Skill 声明的暂停点不可被跳过**。"

核实结论——**这句话指的东西已经不存在了**：

- `manifest_schema.py:100`：`flow.steps / step_stages / dependencies` 是 `DEPRECATED_FLOW_KEYS`，**声明即 fail-hard 拒注册**；
- `manifest_schema.py:241`：`_check_stage_overrides` 已被掏空（"声明忽略不校验，恒用平台默认定义"）；
- `parse_pause_rules`（`registry.py:563`）唯一消费者是 `skill_docs.py:533` 的 **工作台 lint 提示**，没有运行时消费者；
- 散文里的"何时暂停："是给人/模型读的，**平台不解析**。

**即：skill 里没有机器可读的暂停点声明，平台也没有"不可跳过"的实现。**

**另有一处同类失真**（顺带修）：`skill_docs.py:629` "平台将以**机械卡/闸形态兜底**"——这个兜底从未存在（3333 四暂停点零触发即为证）。

## 三、总体思路（一句话）

> **平台负责"落得下、看得见、会喊疼"；模型负责"走到哪、该不该停"。**

这不是拍脑袋，是 Flova 一手转录（凡人修仙传项目）里读出来的：

| 观察 | 转录原文 |
|---|---|
| 进度是**模型自述**的，平台只发事实事件 | "✅ 制作规格已确立 / ✅ 分镜设计完成 / **下一步：角色声音锚定（Step 4b）**"——平台从头到尾没算过"你在第几步" |
| **没有流程硬闸** | 全程只有"请预览…满意后告诉我"，零次机器拦截 |
| **低成本产物不停** | 规格 → 分镜 → 4 张元素图一路跑通，一个确认都没停，尽管 skill 的"何时暂停"列了这些点 |
| 真正停的只有四类 | 缺输入（声音参考文件）/ 高成本批次（18 镜分批）/ 花钱产物确认 / 决策点（方案 A/B） |
| 每一步都有事件卡 | `Skill已完成`/`视频规格已完成`/`故事板已更新`/`Media Assets已完成`/`媒体变更已同步` |
| 失败会喊 | `编写提示词失败` → 修正参数 → 重新提交 → `编写提示词完成` |
| 规格是活的 | 改 1080p 时"先更新制作规格文档，然后继续补全未完成的镜头" |

**Flova 的秩序不来自拦截，来自"落得下、看得见、失败了会喊"。我们缺的正是这三样。**

## 五、验收总口径（16 份 skill 冒烟）

每份 skill 跑标准输入，断言四条：

1. **首步正确**——商品宣传片的首步是"写规格"，不是"剧本分析"（按各自 skill 的尺子）；
2. **每步有产物落地**——不是只有聊天正文；
3. **三类停点真发卡**——缺输入 / 高成本批次边界 / 决策点（**不是** skill 散文里每一个"暂停"字样，见 §六待决点 3）；
4. **能走到最后一步**——流程不卡死。

补充断言（转录修正）：
- **启动协议是条件式**：缺项必问、不缺可跳且说明理由（不是无条件三问）；
- **低成本产物不停**：规格、故事板、元素图跑完就往下走，不弹无意义的确认。

> 断言 3 的判据来源：从 skill 的`何时暂停：`行解析（16 份格式一致，已核对 5 份；`依赖关系：`行有异类——宣言式是散文体——**只作测试判据，不进运行时**）。

## 六、待决点（需要你拍板）

### 1｜设置页那句文案改成什么？

| 候选 | 文案 | 评价 |
|---|---|---|
| **a（推荐）** | "任何档位下：未注册工具、文档写入与画布操作等高危动作照常拦截；生成类动作按所选档位处理。" | 只说真话，不承诺未实现的；档位语义不变 |
| b | 保留"暂停点不可被跳过"，并把三类停点（缺输入/高成本/拍板）真正实现 | 承诺更重，实现量也更大 |
| c | 改为"缺输入必问、高成本批次与决策点必停" | 与 Flova 实测语义一致，但要新建判定逻辑 |

**倾向 a**：先把假话说成真话，实现的事由冒烟结果决定（见待决点 3）。

### 2｜"下一步建议"按钮怎么办？

现状：`current_node_title` 拿**平台统一 8 节点图**算，量异构 skill 会失真（商品宣传片无分析阶段、宣言式 13 步 → 恒显示"剧本分析"，3333 同款症状复发）。

| 候选 | 做法 |
|---|---|
| **a（推荐）** | 改为**事实缺口派生**：不显示"第 N 步"，只显示"还缺制片规格.md"这类客观缺口 |
| b | 交还模型自述（Flova 原样），平台不显示下一步 |
| c | 保留现状，仅修 `sync_run` 每轮调用（异构 skill 仍失真） |

### 3｜暂停语义怎么定？

Flova 实测：skill 散文列的"何时暂停"**没有逐一执行**，真正停的只有四类（缺输入 / 高成本 / 花钱产物 / 决策点）。

| 候选 | 停点定义 |
|---|---|
| **a（推荐）** | 三类必停：缺输入 ∪ 高成本批次边界 ∪ 决策点；低成本可逆产物不停，靠事件卡 + 随时打断 |
| b | 按 skill 散文逐点停（**比 Flova 还死**，会在"规格确认"这种无事可做的点上强迫确认） |

**倾向 a**：先把第 1-3 批做完，**用第 4 批冒烟的实际结果决定要不要加补卡装置**——不靠推理下结论。
