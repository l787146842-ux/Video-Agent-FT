## 二、目标 / 非目标

**目标**
1. SSE 帧带 seq 水位 + keepalive 心跳 + 断口自愈回放：任何断流秒级补齐，灭「整屏死」类。
2. 客户端读模型升投影单元（state/view 分离）：四单元纯折叠账本出读模型，
   各面板值出自同一 asOfSeq 一致切。
3. 暂停卡账本物化：done 帧丢失时，重连 snapshot 仍产出确认卡。
4. 客户端断连诊断日志：服务端 SSE 连接生命周期可取证（D2 登记项）。

**非目标（红线）**
- 不碰 StateManager 唯一写入权威（宪法 Rule 3）：投影只产客户端读模型，不写状态。
- 不做 checkpoint 水印缓存（dsh projection-cache 层）——候选期，见 §八。
- 不改既有组件长相（ConfirmActions/DecisionFormCard/SubagentRail/TimelineDetail 原样）。
- 不碰冻结 #18（KE 覆盖闸）、#12（ref_integrity 扩面）、#16（skill 文本）；skill 一行不改。
- 不改 SubagentRail 轮询口径（二期计划书非目标已登记）；actor 卡归二期计划书。
- 不手改 `src/web/types/api.generated.ts`（contract 闸对账），新字段一律走
  `scripts/gen_api_types.py` 重生成。

## 四、前端方案

1. `lib/sse-connection.ts`（连接状态机）：记 lastSeq；字节级静默满 45s（= 3× 服务端 15s
   注释心跳，零误报；实现期把原拟 2× 放宽为 3×）或 event_seq 断口 → 跳闸自 abort 并按
   可重连处理；重订阅首帧即 replay 快照（修正③：不另设回放端点；重复帧按既有幂等丢弃）；
   重连期间输入区 statusText 复用既有 `rp.streaming.reconnecting`（「连接中断，正在自动重连（n/3）…」）。
2. 新增 `stores/chat/projection.ts`：重连/刷新拉 snapshot 兜底（修正④：不订阅变更帧，
   无 `projection` 新帧型）；活跃暂停而消息尾无载体时物化暂停卡，失败静默不阻断主链。
3. 确认卡数据源：done 帧 payload 优先不变，加投影 snapshot 兜底——末条消息无 confirm
   字段而 snapshot 有活跃暂停时，确认卡挂载末条消息（挂载条件
   `deriveAffordances.confirmTarget` 不变）。
4. 组件长相零变化；新增仅重连状态文案与 projection store。

## 七、风险与回退

- **A 重复投递**：回放与 live 重叠 → 前端按 seq 幂等；后端回放只读无副作用。
- **B 投影与 StateManager 瞬差不一致**：投影只读不写；双跑对比日志暴露差异，
  对比干净前不切消费方。
- **C 性能**：tail 回放读 conv 文件（当前会话体量小）；长会话性能事实出现再立项候选期。
- **回退**：前端忽略 seq/心跳/projection 帧即回现状；后端新增字段与加性端点无害，
  无需回滚。
