# 对画布（画布）项目的需求清单

> 来源：2026-08 集成审查（详见《修复改进计划书-2026-08.md》P0-4）
> 背景：本项目（自己做agent）通过 iframe + postMessage + HTTP API 集成画布。
> 受 ARCHITECTURE_RULES.md Rule 7 约束，本项目不修改画布代码；以下能力只能由画布侧实现。
> 本项目侧曾预留的收发协议（canvas:ready / canvas:selection / studio:draft-select）因画布侧从未实现，已按审查结论移除，当前唯一生效的 postMessage 通道是主题同步；**待画布侧实现本清单后，需在 `src/web/lib/canvas-bridge.ts` 按此重新接入**。

## 需求 1：`canvas:ready` 握手消息

**场景**：画布 iframe 加载完成后，主动向父窗口广播就绪信号。

**建议实现**：画布页初始化完成后执行：

```js
window.parent.postMessage({ type: 'canvas:ready' }, '*');
```

**价值**：本项目可精确感知画布就绪/重载时机，用于清除过期选中缓存、触发状态同步，替代目前的超时猜测。

## 需求 2：`canvas:selection` 选中态广播

**场景**：画布内选中变化时（选中/取消选中图片、视频等节点），向父窗口广播当前选中集合。

**建议消息格式**（本项目已按此格式解析，含相对地址补全与 URL 去重）：

```js
window.parent.postMessage({
  type: 'canvas:selection',
  items: [
    { url: '/assets/xxx.png', name: '场景概念图', kind: 'image', nodeId: 'node-xxx' },
    // ...
  ],
}, '*');
```

**价值**：目前 Agent 对话的 @ 提及无法感知画布内选中（选中态只存在于画布浏览器端内存，服务端不持久化、无 API），只能回退到"全部画布素材"。实现后 Agent 可精准操作用户选中的素材，是集成体验提升最大的一项。

## 需求 3：`canvas:node-select` 反向选中回传

**场景**：用户在画布中点击某节点时，向父窗口广播节点 id。

**建议消息格式**：

```js
window.parent.postMessage({ type: 'canvas:node-select', nodeId: 'node-xxx' }, '*');
```

**价值**：本项目可将画布点击联动到故事板对应草稿卡片的选中，实现双向联动。

## 需求 4（可选）：`canvas:node-update` 节点数据变更广播

**场景**：画布节点内容（如图片替换、文案修改）变化时广播 `{ type: 'canvas:node-update', nodeId, data }`。
**价值**：保持故事板与画布内容一致，减少手动刷新。

## 需求 5（可选）：放开或收窄跨源消息校验

**现状**：画布画布页 message 监听对跨源消息直接丢弃（`event.origin !== location.origin` 时 return），导致本项目发送的 `studio:draft-select` / `studio:state-sync` 无效。
**建议**：若画布希望支持被嵌入集成，可改为白名单校验（允许配置的父窗口源），而非仅同源。本项目的主题同步（`studio-theme`）之所以生效，正是因为 `theme.js` 未做 origin 校验。
