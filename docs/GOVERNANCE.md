# GOVERNANCE — 指令治理条款（唯一家）

> 本文件是治理条款的**唯一表述源**（P1）：内容为原宪法第十三章 / 指令治理层（GOVERNANCE）的活条款，
> 原卷整卷归档见 git tag `governance-archive-20260901`；裁决与批次留痕见 `CHANGELOG.md`。
> 其他层（`AGENTS.md` §八、`ARCHITECTURE_RULES.md` 头部与 §十二）只放指针，不复述本文件条款。

## 一、三原则

- **P1 单一事实源**：每条规则只有一个表述源，其他层只能引用不得复述；引导与校验冲突时以代码校验的客观结果为准并修表述。
- **P2 约束下沉**：能被代码机械校验的一律实现为代码校验（拒收/修正），禁止用「严禁/必须」prose 说服模型；代码校验只裁定模型产出的格式与客观状态，不拦用户意志。
- **P3 状态即数据**：注入给模型的状态/工具结果必须是纯客观数据，引导语独立且极短，禁止把说教嵌入数据体。

## 二、修复决策树

先查现有机制 / 下一代模型是否已覆盖（证明不覆盖才新增组件，且新增组件须有回归测试覆盖）
→ 定位规则唯一定义层（找不到归属 = 新规则按层安家）
→ 能代码校验就下沉、不能则只改唯一定义层
→ 清除其他层分身
→ 回归测试带事故编号。

确定性三问判别：答案可算＋机器可判＋无创作空间 → 收归系统；仅可判 → 模型写、系统验收；都不是 → 留模型、人审。

## 三、捷径禁令

禁止在事故现场就近补条款；同一规则不得两层以上新增表述；新增 prose 禁令前必须回答「为何不能被代码校验」。

## 四、方案四关（G1-G4）

- **G1 Skill 改动裁决关**：Skill 改动不得以降低 Skill 要求的方式迁就系统缺陷，优先修平台层；例外须用户显式裁决。
- **G2**：出方案前先查既有机制（缺口假设须 eval 证明）。
- **G3**：禁止「写一句话让模型配合机制」式 prose 方案。
- **G4**：事故修复覆盖同类全部调用路径（统一策略 + 钉死回归）。

## 五、指令体量 / 门禁登记 / 错误信封

- **指令体量**：planner 系统提示词（`prompts/planner/`）展开后保持精简、靠人工审核控制体量（原「≤7KB 机械预算闸」已随 2026-09-02「治理闸机减负」裁决退役，不再机械强制、亦不恢复机械闸）；回喂话术单条 ≤ 3 句；同一规则定义处恒等于 1。
- **门禁登记**：新增门禁脚本在 `scripts/acceptance.py` GATES 或 RATCHETS 表同步登记；闸机增减由用户裁决（宪法 §2.3）。
- **错误信封必须抛错**：适配器层识别上游拒收并抛错（不当稿子），错误展示走人话 + 原文折叠。

## 六、治理限速

全面审核报告每季度至多 1 篇；不再开「第 N 轮」修复计划书，清偿动作唯一载体是 `docs/未清偿债务清单.md`（清偿一条、清单删一条）。
