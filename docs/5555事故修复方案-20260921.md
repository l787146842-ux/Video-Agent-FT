### Q3 暂停卡问句是系统生成的 —— 确认是设计，但**阶段标签回落是真缺陷**

`pause_composer.split_pause_channels()`：
```python
short = f"「{stage_label or '本阶段'}」已完成，请过目以上成果并选择下一步。"
return short, model_message      # 模型原文 → 正文通道（pause_overflow）
```

**缺陷**（实跑落盘取证，`chatMessages[1].confirm`）：
```
'「本阶段」已完成，请过目以上成果并选择下一步。'      ← 标签回落到 "本阶段"
```

**根因链**（三跳，缺一不可）：
```
父代理暂停轮唯一工具 = run_subagent
  → fc_tool_runner._commit_call:  _stage_lbl = stage_label_for_tool("run_subagent")
  → registry.STAGE_LABELS 只登记工具名，run_subagent 不在表内 → 返回 ""
  → last_stage_label = ""  → 暂停卡渲染「本阶段」
```
子代理内部那次 `script_analysis_report` 跑在**子级自己的 runner 实例**上（`planner._launch_subagent` 新建 `Planner`），父级 `last_stage_label` 看不见。

**结论**：**委派出去的阶段，父代理的暂停卡拿不到阶段标签** —— 结构性缺口，可复现。

## 三、取证期追加发现（不在用户 8 问内，但是真缺陷）

> 这两条是我在核实 Q3/Q8 时顺带查出的，**属同一根因族**（「子级上下文组合缺件」），建议一并修。**是否纳入请你裁决**。

### 追加-1：子代理收到**自相矛盾的路由指令**（G3 级缺陷）

**实测**（复刻 key_elements 子级 context 跑 `build_state_tail_message`）：

```
===== UNAVAILABLE =====
以下工具本轮不可用：…, run_subagent, …
替代路由：经委派（run_subagent）执行对应阶段。
```

**但 `run_subagent` 就在子级的 deny 集里**（`SUBAGENT_TOOL_DENY` 第一条 = 结构防递归）。实测 `_compute_excluded_tools` 子级分支：`run_subagent` / `image_generate` / `read_skill` **全部在 `turn_excluded` 内**（子级 deny 集整体并入裁剪集，`planner.py:359-361`），于是**被子级 deny 的工具全部被渲染进 UNAVAILABLE 段**。

**性质（比"指路不可达"更严重）——三层自相矛盾**：

| 层 | 说什么 |
|---|---|
| UNAVAILABLE 段 | 「`run_subagent` 不可用，**替代路由 = 经委派（run_subagent）执行**」 ← **用被禁的工具当被禁工具的替代** |
| `SUBAGENT_POLICY` 段 | 对子级**不注入**（`_sec_subagent` 在 `subagent_depth≥1` 时 return ""），文案无冲突 |
| 渲染逻辑本身 | 该段文案是给**主代理**写的（主代理面被裁 = 该走委派），**对子级是语义反的**：子级被裁 `run_subagent` 是**结构防递归**，不是"改用委派" |

**根因**：`turn_excluded.md` 的替代路由文案是**面向主代理单场景**写死的常量（`prompt_builder.py:225` `_excl_route = "经委派（run_subagent）执行对应阶段"`），而 `turn_excluded` 这个通道**被子级复用了**（子级 deny 集并入裁剪集）。同一段文案套到子级就变成循环指令。

这正是 G3 要防的「写一句话让模型配合机制」，只是方向相反 —— **机制没配合文案**。

### 追加-2：子代理的 system prompt 里，`protocol.md` 指向两份它拿不到的文件

**实测**：`protocol.md`（**整文件、无 depth 门控**，1201 字）注入子级，其中两句是**悬空指针**：

| `protocol.md` 原句 | 子级实际 |
|---|---|
| 「停轮与批次时机见**《Skill 流程纪律》第 6 条**（本协议不复述）」 | `skill_runtime.md::DISCIPLINE` 只在 `_selected_block`（`skill_name` 非空）里注入 → 子级**拿不到** |
| 「防虚报：…（唯一细则见**《Skill 流程纪律》第 3 条**）」 | 同上 |

**叠加后果（与 Q8 直接相关）**：`protocol.md` 说「批次时机见《Skill 流程纪律》第 6 条」，而子级**既拿不到纪律、也没有代替品** —— `DELEGATION_CONTEXT` 只有「批次之间禁止纯文本汇报轮」，**没有「每批 3~5 个」、没有「不要一次生成全部」**。

**即：Q8 的分批纪律丢失，不只是"没注入"，而是"被 protocol 明确指路到一个空地址"。**
