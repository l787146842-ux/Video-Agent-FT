# 配置说明

> 本文档梳理本项目全部配置源的**权威关系与加载优先级**（计划书 P1-7）。
> 原则：每类配置只有一个权威源；环境变量仅用于覆盖/部署差异，不承担业务数据。

## 配置源总览

| 配置源 | 角色 | 是否入库 | 读/写方 |
|---|---|---|---|
| 根目录 `.env`（模板 `.env.example`） | **运行参数**：端口、画布地址、记忆后端、安全开关等 | 否（gitignore） | `config.py::load_dotenv()` 启动时加载 → `settings` |
| `API/.env` | **第三方 API Key 唯一存放地** | 否（gitignore 第 3 行） | `web/provider_config.py` 读取；api-settings 页面写入（带消毒与锁） |
| `data/api_providers.json` | **供应商列表与模型配置的权威源（配置文件，豁免入库 sqlite，任务 #24）** | 否（data/ gitignore；技能文档除外，见下） | `provider_config.load_merged_providers()`；api-settings 页面读写 |
| `data/canvas_integration.json` | 画布版本漂移记录 | 否（data/ gitignore） | `canvas_adapter.check_version_drift()` 自动维护 |
| `prompts/**` | 外置 Prompt（Rule 6） | 是 | `utils/prompts.py::load_prompt()` |
| `workspace/state.sqlite3` | 项目状态唯一事实源（StateManager，Rule 3；任务 #24 镜像退役：JSON 镜像与 studio_state.json 停写，首启从旧文件一次性导入） | 否 | 仅 StateManager（经 repository）可写 |
| `workspace/state.sqlite3` kv 表 | agent/generation 任务表 + 生成日志（任务 #24 自 data/*.json 迁入，带事务 KV） | 否 | `web/agent_task_manager.py`、`web/task_manager.py`（经 `web/task_store.py`） |

## API Key 解析优先级

`provider_config._resolve_api_key()` 按以下顺序取第一个非空值：

1. **进程环境变量**（如 `OPENAI_API_KEY`）
2. **本项目 `API/.env`**
3. **画布 `API/.env`**（仅当设置了 `CANVAS_ENV_FILE` 且该 provider 来源于画布）

> 计划书曾提到 `agent-config.json` / `canvases.json` / `appinfo.json` 三个文件——
> 经核实现状：它们**不属于本项目**，是画布侧的数据文件。本项目只通过 HTTP
> 与其交互（`GET /api/providers` 合并供应商、`GET /api/app-info` 探测版本、
> `/api/canvases` 读写画布），从不直接读其本地文件（Rule 7）。

## 供应商配置的合并规则

最终生效的 provider 列表 = **本项目 `data/api_providers.json`** 与
**画布 `GET /api/providers`**（HTTP，带缓存，TTL=`CANVAS_HEALTH_CACHE_SECONDS`）合并，
同 id 时以本项目条目优先。画布离线时静默降级为仅本地列表。

可选增强（默认关闭）：设置 `CANVAS_PROVIDERS_FILE` / `CANVAS_ENV_FILE` 直接指向画布的
本地配置文件，用于离线场景；默认留空，全部走 HTTP。

## 环境变量清单（根目录 .env）

完整清单以 `.env.example` 为准，关键字段：

| 变量 | 默认 | 说明 |
|---|---|---|
| `PORT` / `HOST` | `8080` / `127.0.0.1` | 服务监听（勿与画布 3000 冲突） |
| `ENVIRONMENT` / `API_KEY` | `development` / 空 | production 时 `/api/*` 强制 `X-API-Key` 校验 |
| `CANVAS_BASE_URL` | `http://127.0.0.1:3000` | 画布地址 |
| `CANVAS_ENABLED` | `true` | 关闭后所有画布功能降级 |
| `AGENT_MAX_STEPS` | `6` | Agent 多步循环上限（Rule 2） |
| `STATE_BACKEND` | `sqlite` | `json` / `sqlite`（默认 sqlite 且为唯一事实源；首启自动从旧 JSON 一次性导入；镜像已退役，sqlite 写入后回退 json 不再无损） |
| `SNAPSHOT_MAX_PER_PROJECT` | `20` | 每项目快照数量上限（淘汰策略见下节） |
| `STORAGE_BACKEND` | `local` | `local` / `s3` |
| `LOG_FILE_ENABLED` | `true` | 日志文件落盘开关（六轮 S4）：测试/验收进程经 conftest 与 acceptance.py 自动置 false，防多进程争用日志文件；服务进程保持默认 |

代码中禁止硬编码可调参数（ARCHITECTURE_RULES §二）：新增可调项一律加到
`config.py::Settings` 并在此表登记。

## 快照数量上限与淘汰策略

快照（对话分支/工作流快照，`workspace/snapshots/<项目>/`）按项目限流：

- **上限**：每项目最多保留 `SNAPSHOT_MAX_PER_PROJECT`（默认 20，≤ 0 按 1 处理）；
- **淘汰时机**：仅在**创建新快照之后**触发，新创建的快照永不被当次淘汰；
- **淘汰顺序**：按创建时间升序淘汰最旧（创建时间优先读文件名编码的
  时间戳，存量/改名文件回落读正文 `created_at`，损坏或缺字段视为最旧）；
- **pinned 豁免**：创建快照时可声明 `pinned: true`，pinned 快照不参与
  淘汰（豁免名单存旁路索引 `_pinned.json`）；
- **淘汰可见**：被淘汰的快照 id 清单随创建响应 `pruned` 字段返回，
  前端收到非空清单时弹 toast 提示「为控制数量，已自动清理 N 个最旧快照」；
  淘汰为不可逆删除，引用已淘汰快照的分支操作会收到 404（分支对话本身
  已装载的消息不受影响）。

## 运行时数据（均不入库）

- `workspace/state.sqlite3`：项目状态 + 任务表唯一事实源（任务 #24 收敛后）
- `workspace/`：生成资产（storage 模块管理）；`projects/*/state.json`、
  `projects/index.json`、`studio_state.json` 为已退役镜像/兼容文件，
  仅首启导入时读取，不再写入
- `data/skills/*.md`：技能文档（可在 UI 内新建，写入即落盘）
- `data/agent_tasks.json` / `data/generation_tasks.json`：已迁入 sqlite kv 表，
  仅作首启一次性导入兜底，停写保留只读一个版本周期后移除
- `data/demo_state.json`：首次启动种子状态（只读夹具，非运行时数据）
- `data/runtime_settings.json` / `data/video_batch_tasks.json`：运行时开关与
  视频批量台账（本次收敛范围外，归属维持现状）
- `logs/`：loguru 日志（按日滚动）

## 修改配置的注意事项

1. **密钥只进 `API/.env`**，不要写进根 `.env`（根 `.env` 可能被提交模板化）；
2. 增删供应商改 `data/api_providers.json`（或用 api-settings 页面），**不要**改代码默认值；
3. 对接新版画布后：启动日志若出现版本漂移 warning，按
   [tests/fixtures/canvas/README.md](../tests/fixtures/canvas/README.md) 刷新契约夹具并跑契约测试。

## 本版本移除的对外端点清单（影响面审查 FIX-4）

以下端点已从路由层整体移除，外部集成方请按下表迁移：

| 已移除端点 | 替代路径 | 说明 |
| --- | --- | --- |
| `POST /api/agent/chat/stream` | `POST /api/agent/tasks` + `GET /api/agent/tasks/{task_id}/events` | 对话改任务式：先建任务拿 task_id，再走 SSE 事件流订阅进度 |
| `POST /api/agent/stop` | `POST /api/agent/tasks/{task_id}/stop` | 停止按任务维度（原全局停止无对应物） |
| `GET /api/agent/running` | `GET /api/agent/tasks`（可带 `project_id` 过滤） | 运行状态改从任务列表查询，逐任务读 status 字段 |
| `/api/memory*`（全组） | 无 | 记忆功能已整体退役，无替代路径 |

另：`GET /api/conversations` 列表响应不再携带 `messages` 字段（体积收敛）；
需要消息请逐对话调 `GET /api/conversations/{conversation_id}/messages`。
