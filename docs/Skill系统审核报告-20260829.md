# Skill 系统审核报告（正向设计 · 业界对标版）

> 日期：2026-08-29。依据：项目内全链路审计（全部结论附代码证据）+ 四家业界对标
> （Flova / Claude Agent Skills / Codex / DeepSeek Harness，逐格标注确认/推断/缺失）。
> **本报告已按 2026-08-29 用户多轮裁决刷新**，裁决全文见文末第七节，与本文冲突时以裁决为准。

## 一、总评

这套 Skill 系统的主干与业界最高水准同构：单一包形态对齐 Agent Skills 开放标准、
三级渐进披露对齐公认基线、选择双模式（用户显式 / 模型自主）对齐四家共同做法、
素材版本锁对齐 Flova 独家机制。经本轮审核与用户裁决，系统哲学收敛为一句话：

**Skill 内容信任作者，平台只守自己的机械边界（确认闸 / 动作单轨 / platform 闸不可关）。**

| 面向 | 结论 | 大白话 |
|---|---|---|
| 包形态与契约（`<slug>/SKILL.md`、name/description 必填、注册期拒坏包） | **对齐**（Claude/Codex/dsh 同一开放标准，Flova 为视频私有格式） | 每个 skill = 文件夹+说明书，开头必须写清名字和用途，写不清拒收 |
| 三级渐进披露（目录常驻→选中预算注入→续读/资源按需） | **对齐**业界基线，代码与宣称逐一对应 | 先给菜单、选中给开头、其余按需读，不把整本手册塞给模型 |
| 选择双模式（开关+显式选择 / 模型自主判断） | **对齐**（dsh 已类型化为调用策略） | 你指定，或模型看着办，两条路都是正式功能 |
| 素材携带 + sha256 版本锁 | **对齐 Flova**（机制在场、存量未启用） | 可带素材、按文件指纹锁版本，防偷换 |
| 注入防御（正文机械中性化） | **用户裁决：全部砍除**（业界本就无人做；回归作者信任 + 机械边界兜底） | 不检查正文里的骗人话；真花钱的动作照样有确认闸拦，骗不过钱包 |
| 成本确认 | **用户裁决：对齐 Flova**——三档执行偏好 + 草稿两段式；金额分级、保存前差异对比不做 | 拦不拦由你按项目设档位；花钱前先给草稿确认 |
| 工具名白名单 / 禁令账本（本项目自造门禁） | **用户裁决：全部删除**（业界无同款，不设此类限制） | 不检查手册里写了什么工具名、不统计"严禁/不得"数量 |
| 字数类质量键（如分镜提示词最少字数） | **用户裁决：skill 完全自主**，平台不加"不得低于地板"约束 | 创作标准由 skill 作者定，平台值只是没声明时的默认 |
| 不含可执行脚本 | **维持**（与 Flova 一致；本项目无沙箱，脚本执行走 MCP 通道管着） | 手册就是手册，不带可执行代码 |

## 二、内部互验结果（宣称与代码对质）

### 2.1 经得起对质的（保留结论）

- 三级披露宣称与代码一一对应（目录组装/选中注入/续读三段均在）。
- 机械防线中**确认闸、动作单轨、platform 闸不可关**三道真实在场（继续保留）。
- 单一包形态彻底：16 个存量包全为 `<slug>/SKILL.md`，name/description 全量在场。
- 前后端章节标签体系 18/18 真等价（注意真实数字是 18，旧文书写 17 系笔误）。
- 素材版本锁/开关/预算注入三机制对存量 16 包正交无冲突。
- 测试密度扎实，关键行为均有钉死测试（随删除项同步清理）。

## 三、业界对标要点（审核依据）

1. **Agent Skills 已成事实开放标准**：Claude / Codex / dsh 三家同一契约
   （`SKILL.md` + frontmatter name/description），仅 Flova 为视频领域私有格式。
2. **三级渐进披露是公认基线**：元数据常驻（每条约百 token）→ 选中读全文 →
   附属按需；"按需"指**按需读全文，不是按需找技能**。
3. **规模拐点有官方口径**：Anthropic Tool Search Tool 阈值（定义 >10K tokens
   或 10+ 个转按需发现，准确率 49%→74%）；学术（Li 2026）证明选择准确率
   相变崩溃、根因是相似 skill 语义混淆。对策：层级路由 + 开关预过滤。
4. **素材版本锁最优解 = Flova「发布即冻结 + 副本分发」**：同时解决作者改动
   影响使用者与素材丢失；本项目若做分享（L21）照此设计，不做活引用。
5. **外部信任主流 = 来源标记 + 人审 + 沙箱三件套**，无一家全自动审核；
   本项目已做来源标记 + source 分口径；因 skill 不含脚本，沙箱风险面天然更小。
6. **description 是路由契约**：Claude/Codex 官方均要求打磨描述 + 用真实轨迹
   评测选择准确率——本项目暂无此层评测（见扩展方向）。
7. **脚本执行**：Claude/Codex 带沙箱故执行脚本；Flova 与本项目同为
   「纯文本手册+素材」，不含脚本执行——与对标锚点一致。

## 五、今后的扩展方向（登记不排期，均有业界出处）

| 方向 | 业界依据 | 衔接 |
|---|---|---|
| 选择准确率评测（description 路由契约校准） | Claude/Codex 官方方法论 | 挂 L1 评测双轨 |
| 规模化换档阈值（>10K tokens / 选择准确率下滑 → 层级路由或按需发现，3-5 个常驻） | Anthropic Tool Search + Li 2026 | 补进非目标第 6 条例外边界 |

## 六、明确不做（用户裁决，机械防线外的自由地带）

1. **不做正文中性化**：不检查/不消音 skill 正文任何句式（含"用户已同意"类）；
   后果自担哲学——装外部 skill 视同装软件，审核责任在装的人（Anthropic 官方同口径）。
2. **不做工具名白名单、不做禁令账本**：业界无同款，本项目不设此类创作限制。
3. **不做字数地板强制**：质量键由 skill 自主声明。
4. **不做 skill_search 按需检索**（非目标 6）：业界 = 目录元数据注入 + 模型判断
   + 按需读全文，"按需"指读全文不是找技能。
5. **不做社区 + 排序/搜索前端**（非目标 7）：暂无必要。
6. **不做保存前差异对比、不做按金额分级暂停**（本轮裁决）。
7. 红线仍在（不因上述放开而松动）：§2.4 Context≠Consent（确认闸机械执行）、
   动作单轨、platform 闸不可被 skill 关闭、scripts 键只静态校验绝不执行。
