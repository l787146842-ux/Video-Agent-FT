# 指令收拢与缓存稳定执行计划（正向设计批）

> **立项依据**：1111 项目复盘（思考打架 / 正文差 / 缓存命中 20.9%）+ 用户裁决（2026-09-08/09：Skill 包一行不改；Skill 装载期校验不做、记长期规划；工具全量常驻；缓存命中稳态目标 ≥95%）+ 外部一手调研（Codex 官方 `gpt_5_1_prompt.md`、Claude Code 系统提示词逆向、DeepSeek Harness 官方架构笔记——三家均开源可查证）。
> **设计总原则**（落地 DeepSeek Harness「every fact in the prompt has exactly one owner」治则 = P1 在 prompt 层的执行）：提示词里的每条事实有且只有一个所有者；机制归机制（闸机），叙述归叙述（分节）；静态核心与动态尾巴显式分界。**本计划不新增任何 prose 禁令，只做既有表述的收拢与退役（净减指令）。**

## 一、现状与根因（带数据）

**缓存基线**：`data/cache_metrics.jsonl` 全量 145 样本命中率 **20.9%**；近期项目 0~37.5%（每轮首调 0 命中、轮内翻转点清零、命中值停在 system 头部几千 token 不动）。

三层击穿（代码实证）：
1. **每轮必中**：前端 10 条消息窗口（`submit-message.ts` `slice(-CHAT_HISTORY_WINDOW)`）+ `truncate_history` 位置相关截断（最新 assistant 2000 字 → 更早 300+300，同一条消息跨轮被改写字节）→ 消息区前缀每轮从 byte 0 失效；
2. **轮内翻转必中**：阶段工具裁剪每步重算（建组后 `generate_video` 释放进 tools）+ system 条件段 `_sec_global_settings` 同刻凭空出现 → tools 与 system 双击穿；
3. **每步全价**：状态尾部消息每步重建且不入历史（设计内代价，~1.5-2.5K tokens/步）。

思考打架（判定源散布）：停/问/继续三类判定散布 5 处（protocol「可直接继续」、《Skill 流程纪律》第 2/10 条对冲、状态尾部边界注释、工具 description、STEP_FEEDBACK 定向催促「请继续完成任务」）；防虚报 4 处重复；裁决留痕（「也不设平台拦截」「机械越阶拦截已退役」）泄漏进每轮运行时文本；Skill 内部矛盾（「每个阶段完成后必须暂停」vs「4 个重点暂停点」；启动协议「按顺序确认」vs 平台一次性分组收集）只能靠模型脑内司法审查。

正文差：回复输出纪律 4 条全是抑制性条款（不复述/不罗列/要简短），无正向锚点、无范文；多步循环把每步过渡语跨步拼进正文；机械占位文案（「已执行 N 个操作」）入历史成为 few-shot 污染，反向教会模型「正文长这样」。

## 二、用户裁决（本计划边界）

1. **Skill 包（data/skills）一行不改**；Skill 装载期所有权校验**不做**，记长期规划（登记 `docs/冻结与暂缓清单.md`）。
2. **工具全量常驻**（Claude Code 形态）：注入面裁剪退役，正确性由闸机 + 工具自身校验承担。
3. **缓存命中稳态 ≥95%** 为验收目标。
4. **闸机（fc_gates 链）零增减**：退役的只是「注入面裁剪」（软层，原注释自认「裁剪只是第一层（软）：由既有闸机做第二层兜底」）；tool_risk / gen_confirm / structure_integrity / 轮末阶段闸全部保留。

## 三、分批改动清单

### 批 A 指令所有权收拢（纯文本层，零机制变化）

判定式唯一化——「何时停 / 何时问 / 何时继续」各只剩一处表述：

**A1 `prompts/planner/skill_runtime.md`**
- 纪律第 2 条开头重写为**唯一停机判定式**：「何时停（唯一判定）：所选 Skill『关键暂停点/何时暂停』声明的暂停点 + 平台硬闸（花钱生成确认、执行模式阶段闸）→ 必须调用 workflow_pause 真停并结束本轮；其余任何时刻（批次间隙、启动问询、结构搭建中途）一律不停、不发卡。只在正文写『请确认』而不发暂停信号 = 无效假停。」三态回应 / message ≤120 字 / 分组收集等机制细则原文保留。
- 纪律第 1 条删「（机械越阶拦截已退役…）」裁决留痕括号。
- 纪律第 10 条删「小步推进≠小步暂停：批次之间不停顿、不发暂停卡等确认，直到阶段完成到达 Skill 暂停点、或进入花钱生成前（…）」整句（判定式已覆盖），只留批次节奏（3~5 个）与思考分批。

**A2 `prompts/planner/protocol.md`**
- 开场盘点段删「，也不设平台拦截」；「缺什么问什么」后补「缺项合并为一次问询（一条正文或一张带分组的暂停卡），不逐题多轮往返」。
- 回复输出纪律 4 条按 Codex 三段式重写为**正向契约**：①声明「工具调用之间的每个字都是给用户看的正文」（过渡语=正文）；②中间更新 1~2 句、只报有信息量的进展（附 2 条例句）；③收尾 recap = 本轮做了什么一句 + 要点 1~3 条 + 下一步建议（原三段式保留）；④成果全文归事件卡/草稿卡、正文浓缩交代（原条款语义保留）。

**A3 `prompts/shared/iron_rules_header.md` + `src/video_agent/core/spec_rules.py`**
- 头部（优先级链唯一表述源）补缺信息分支：「信息缺失且 Skill/流程要求询问 → 先问再做，不擅自补全；用户明确指令与本文档/制片规格/Skill 冲突 → 先照常执行，回复末尾警告。」
- 默认《执行铁律》模板删第 1 条（与头部同义复述，P1 违例）；**存量项目铁律文档属用户数据不动**，残留语义与头部相容、被头部声明覆盖。

**A4 `prompts/planner/feedback.md` + `src/video_agent/core/agent_loop.py`**
- 新增 `STEP_FEEDBACK_AT_PAUSE` 分节（≤3 句，符合回喂体量规约）：「（系统）第 {{step}} 轮的 {{count}} 个 Tool 已执行完毕，工作台状态已刷新。当前已到达所选 Skill 声明的暂停点：请立即调用 workflow_pause 呈现本阶段成果并结束本轮。」
- agent_loop 每步回喂时经**既有客观探针**（与轮末阶段闸同一判定源，`stage_probes`/workflow_runtime）判定「已到暂停点」→ 换用该模板。消除「请继续完成任务」在暂停点上的定向催促对冲；确认档机械闸行为不变。

### 批 B 工具常驻 + 组装单一化（机制层，闸机零变化）

**B1 `src/video_agent/core/planner.py`**
- `_compute_excluded_tools` 删除阶段裁剪分支（skill+strict 下 `stage_tool_restrictions` 调用与 `stage_note` 签发）；保留 use_studio_context / canvas 探针 / MCP 白名单三源；**计算时点从每步（`_build_system_prompt` 内）移到轮始一次**，轮内冻结。
- 效果：tools schema 跨步字节稳定（canvas 翻转 / MCP 启用变更天然落在轮界）。

**B2 `src/video_agent/core/prompt_gates.py`**
- `stage_tool_restrictions` / `STORYBOARD_STAGE_TOOLS` / `GENERATION_STAGE_TOOLS` 退役删除。
- 早于结构就绪的 `generate_video` 调用由第二层兜底（现状已具备）：工具自身校验（未配置供应商/草稿未就绪 → validation 拒）+ gen_confirm 确认闸 + 判定式指引；失败回喂带保留声明与补救指引（既有 B5 机制），不产生状态污染。

**B3 `src/video_agent/core/prompt_builder.py`**
- `_sec_global_settings` 改**无条件注入**（内容极小且极少变化；消除「首组建组后中段凭空出现」的翻转击穿）。
- `_sec_iron_rules`：核实铁律文档 ensure 时点（项目初始化即建则天然稳定；若非，改为无条件注入骨架段）。
- `_sec_selected_draft`（order 75）从 system 移入状态尾部（UI 选中态属每步可变事实，P3 归位）。
- stage_note 消费段删除（A/B 后无生产者）。

**B4 组装单一化（dsh `PromptAssembly{sections, tools}` 形态）**
- planner 暴露单一组装入口 `build_request_assembly(context) -> {system, tools}`（分节与工具 schema 同一拦截点产出）；`turn_executor.call_llm / call_llm_stream` 消费该产物，不再各自向 tool_manager 取 schema。`tools_fp` 指纹观测保留，用于验证跨步稳定。

### 批 C 历史前缀稳定（95% 目标的主战场）

**C1 主路径 history 改服务端线程装载（机制已存在：scope 子对话路径同款）**
- `web/chat_service.py _stream_prepare`：普通请求改走线程装载（新函数复用 `get_conversation_messages` 消息单一来源）；`body.messages` 退役为兼容入参（忽略不报错，老前端不受影响）。
- 前端 `src/web/lib/submit-message.ts`：删除 `slice(-CHAT_HISTORY_WINDOW)` 历史窗口，只发新消息 + conversation_id；`CHAT_HISTORY_WINDOW` 常量退役。**UI 零视觉变化**（展示源本就是服务端 chatMessages 快照，board-sync 注释可证）。

**C2 `truncate_history` 位置无关化（消除跨轮改写）**
- 截断规则改为**消息自身属性**：assistant 内容 >2000 字 → 头 1800 + 尾 200 + 固定省略标记（与「是否最新」无关）；删除「最新一条 2000 / 更早 300+300」双档位。同一消息跨轮字节不变 → 前缀稳定。

**C3 机械占位文案不入模型上下文**
- planner_output / agent_loop 的机械 fallback 正文（「已执行 N 个操作」等）持久化时打 `kind="mechanical"` 标记；线程装载历史时 mechanical 消息压成固定短句（如「（系统动作清单已并入时间线）」）。转换跨轮稳定，不破坏前缀。

**C4 95% 的算术**
- 稳态轮请求 = 稳定前缀（system 静态核心 + tools 全量 + 已见历史）+ 增量（新状态尾部 ~1.5-2.5K + 本步新消息）；随历史增长稳态命中率收敛到 95%+。A/B/C 全落地后以 D1 实测为准。

### 批 D 验收

**D1** 新增 `scripts/cache_hit_report.py`（只读 cache_metrics.jsonl：按项目分组、剔除每项目首个请求，输出稳态命中率与逐请求明细）。**不做 CI 机械闸**（依赖真实流量，机械闸在 CI 无数据可判）——验收口径 = 新项目连跑 5+ 轮后脚本输出 ≥95%，人工判定。
**D2** 测试面：批 A 文本断言同步（protocol/纪律/header 相关）；批 B 退役与改写（`test_hybrid_boundaries` / `test_prompt_gates_branches` / `test_state_tail_injection` 改为「generate_video 常驻 + 闸机兜底」断言）；批 C 新增三组回归（①线程装载口径与 scope 路径同源；②截断位置无关性——同一消息跨轮渲染字节相等；③mechanical 过滤稳定）+ 前端 vitest（历史窗口退役）。
**D3** 流程：每批改完定点验证（pytest 子集 + vitest + tsc），批末 `python scripts/acceptance.py --quick`，终验全量 + `--with-eval`；过一遍宪法 §十二违规检查清单；CHANGELOG 批次留痕。

## 四、暂缓与登记

- `docs/冻结与暂缓清单.md` 新增：**Skill 包不改 + Skill 装载期所有权校验**（用户裁决 2026-09-08：记长期规划，现在不做）。
- `{{变量}}` 通用注入框架（dsh 形态）：本轮不引入（步数/阶段名已由状态尾部承载，无复述病灶）；待 Skill 校验立项时一并评估。
- Skill 文档「按顺序确认」措辞不改（Skill 冻结），平台侧以 A2「缺项合并为一次问询」收口。

## 五、四关自查

- **G1**：Skill 零改动 ✓（用户裁决）。
- **G2**：既有机制已查——服务端线程装载（scope 路径现成）、truncate_history、闸机第二层、tools_fp 观测全部复用，**不新增机制组件**（仅 1 个只读报告脚本）。
- **G3**：无「写一句话让模型配合机制」方案——判定式是既有 5 处表述的收拢（净减）；STEP_FEEDBACK_AT_PAUSE 由代码客观探针驱动；「缺项合并一次问询」暂无法低成本代码校验（连续问询轮检测误判风险高），先 prose 收口 + 观察，诚实标注。
- **G4**：停机判定收拢覆盖全部表述位（protocol / 纪律 2、10 / 边界注释 / STEP_FEEDBACK / 工具 description——后两者随 B2/A4 消解）；历史稳定化主路径与 scope 路径同源装载。

## 六、风险与回滚

| 风险 | 缓解 / 回滚 |
|---|---|
| 工具常驻后模型提前调 generate_video | 确认闸 + 工具校验兜底，最坏一次失败回喂（带保留声明），零状态污染；`tools_fp` 与拒收日志观测，必要时单分支还原裁剪 |
| 服务端线程装载切换 | 线程无历史时回落 `body.messages` 兼容分支，行为不劣于现状 |
| 截断位置无关化使「最新回复保真」降为统一上限 | 最新成果完整语义仍由状态尾部 + 事件卡承载，正文只作对话连续性 |
| 存量项目铁律文档残留旧第 1 条 | 与头部唯一表述源并存、语义相容，随项目生命周期消亡；不做用户数据迁移 |
| 指令体量 | 判定式收拢为净减文本；protocol 新增正向契约 ≈ 替换原 4 条，总量持平略降 |
