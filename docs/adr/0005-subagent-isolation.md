# ADR-0005：子代理隔离（草案——本期不编码）

- 状态：草案（2026-08-27，P2-6 批次产出；未接受，实现需另行立项裁决）
- 关联：受 ADR-0004 约束（模型永远唯一行动主体）；不取代任何既有决策
- 触发：审核项㉑——长任务上下文膨胀与并行能力诉求下，需要「子代理」
  承载局部工作；但 ADR-0004 明确系统不得代替模型发起行动，子代理的引入
  必须先界定其与唯一行动主体的关系，故先出设计草案、本期零编码。

## 问题

1. 单会话上下文随轮次增长（state/skill/回喂叠加），长任务后段窗口压力
   与成本线性上升；段序手术（P2-1～P2-3）只优化缓存命中，不改总量。
2. 部分工作（资料检索、素材盘点、批量校验）天然可隔离执行，不必占用
   主对话的可见上下文。
3. 直接引入「子代理自动干活」会复活 ADR-0003 已退役的机械直跑语义——
   系统代替模型行动，违反宪法 Rule2。

## 拟议决策（待裁决）

1. **子代理 = 隔离上下文中的模型调用，不是新的行动主体**。主模型（唯一
   行动主体）通过工具调用显式发起子任务、接收子结果并决定如何使用；
   系统只提供执行通道与隔离，不代主模型做任何语义决策。与 ADR-0004
   的对齐点：链上每个节点仍是「模型接到输入后自主产出」，代码只搬运。
2. **复用 auxiliary adapter 模式**：会话 compaction
   （web/chat_consume.py:264 附近）已验证「旁路提示词 + 同一供应商
   通道 + 独立消息列表」的形态——子代理通道照此扩型：独立消息上下文、
   独立预算、结果以单条回喂进主上下文；不为子代理新建第二套适配器栈。
3. **隔离边界**：子代理不共享主会话 history，只接收主模型显式给出的任务
   描述与必要原料；产物以结构化结果（文本/引用）回喂，原始中间上下文
   不进主窗口——这是引入子代理的唯一收益来源，回喂全文即失去意义。
4. **可观测同权**：子代理每次模型调用同样遵守「凡入 llm_call 必入
   trace」（P2-6 断言）——可见消息指纹链覆盖子通道，子任务在 trace
   时间线以子步骤形态呈现，审计不因隔离出现盲区。
5. **风险双轴不变**：子代理可调用的工具集仍按 tools 注册表的 risk ×
   approval 双轴校验（P2-5 口径）；隔离不豁免任何闸机，写类高危工具
   默认不进子代理白名单（首期只读）。

## 后果与验收（实现批立项时细化）

- 收益：长任务主上下文增长放缓（隔离工作不占主窗口）；并行检索缩短
  墙钟时间。
- 代价：每子任务至少一次额外模型调用（性能换隔离，与 ADR-0004
  「阶段过渡各花一轮调用」同一取舍方向）。
- 验收基线：trace 指纹链对子通道全覆盖（单测断言）；主模型未显式发起
  时子通道零调用（退役守卫测试防机械直跑复活）。
- 本期承诺：仅本草案入仓，不新增代码、不注册工具、不动闸机。
