## 零、一句话目标

用户选了 skill 之后，agent 顺着这个 skill 的流程一路走到底：
**每一步的产物落得下去、看得见；缺东西会问你；花大钱和要拍板的地方停得住；以后改坏了能被测出来。**

### 关于文案 bug（核实成立）

`ExecutionPreferenceSection.tsx:58` 印着：

> "任何档位下：未注册工具、文档写入与画布操作等高危动作照常拦截，**Skill 声明的暂停点不可被跳过**。"

核实结论——**这句话指的东西已经不存在了**：

- `manifest_schema.py:100`：`flow.steps / step_stages / dependencies` 是 `DEPRECATED_FLOW_KEYS`，**声明即 fail-hard 拒注册**；
- `manifest_schema.py:241`：`_check_stage_overrides` 已被掏空（"声明忽略不校验，恒用平台默认定义"）；
- `parse_pause_rules`（`registry.py:563`）唯一消费者是 `skill_docs.py` 的**工作台 lint 提示**，没有运行时消费者；
- 散文里的"何时暂停"是给人/模型读的，**平台不解析**。

**即：skill 里没有机器可读的暂停点声明，平台也没有"不可跳过"的实现。**

**另有一条同类化石链**（用户裁决 2026-09-05 删整链，见 §四 第 0 批）：`skill_docs.py:629` lint 提示文案"平台将以**机械卡/闸形态兜底**"——这个兜底从未存在（3333 四暂停点零触发即为证）。且该 lint 与 `parse_pause_rules` 解析器构成自产自销闭环（16 份 skill 零声明、无运行时消费者），照 lint 建议补声明也只会让提示闭嘴，运行时什么都不会发生。

## 三、总体思路（一句话）

> **平台负责"落得下、看得见、会喊疼"；模型负责"走到哪、该不该停、下一步是什么"。**

这不是拍脑袋，是 Flova 一手转录四份 + 全局设置页里读出来的：

| 观察 | 证据 |
|---|---|
| 进度与"下一步"都是**模型自述**的，平台只发事实事件 | "✅ 制作规格已确立 / ✅ 分镜设计完成 / **下一步：角色声音锚定（Step 4b）**"——平台从头到尾没算过"你在第几步" |
| **没有流程硬闸** | 全程只有"请预览…满意后告诉我"，零次机器拦截 |
| **停不停的家在全局偏好，两层相乘**【V4-1】 | 客观层（不可配置）：缺输入 / 高成本批次 / 决策点 / 花钱产物四类必停；偏好层（可配置）：全局设置「关键步骤手动确认 / 无需确认」×「素材生成前确认提示词 / 自动生成」——凡人修仙传会话偏"自动"，一路不停；新三份会话偏"确认"，逐阶段停。两层相乘，与 skill 散文无关 |
| 每一步都有事件卡 | `Skill已完成`/`Resource Preparation已完成`/`视频规格已完成`/`故事板已更新`/`Media Assets已完成`/`信息搜索完成`/`媒体变更已同步` |
| 失败会喊，且**声明保留状态**【V4-3】 | `编写提示词失败` → 修正参数 → 重新提交 → `编写提示词完成`；积分不足 → "补充额度后我会直接复用已准备好的方案，无需重新设计" |
| **失败不污染既有状态**（原子性）【V4-3】 | 两次"故事板生成失败（镜头 ID 重复）"，每次都明示"现有故事板没有被改动" |
| 规格是活的，**每次更新都发卡**【V4-2】 | 改 10s 上限 / 定声音方向 / 定无旁白——三次都先更新规格再继续，每次都发"视频规格已完成" |
| 条件式启动 | "根据你提供的完整剧本，脚本确认阶段可以直接跳过"——缺什么问什么，不缺就跳过并说明理由 |
| 提示词草案是**独立产物阶段**【V4-6】 | "草案已准备完成……目前尚未开始生成视频。请审阅后直接回复'确认生成'"——草案与生成解耦，中间留用户确认位 |
| 流程外动作不设闸 | 用户中途让生成电影海报（与短剧流程无关），直接执行无人拦 |
| 可打断可续作 | "您停止了此回复" / "Generation Paused!" / 检测手动编辑后按最新状态重做 |
| **能力边界如实告知** | "当前所用的视频生成方案不支持直接接入音频素材……口型与音色一致性需要根据可用方案进一步确认"（flova3 L461） |

**Flova 的秩序不来自拦截，来自"落得下、看得见、失败了会喊"。我们缺的正是这三样。**

## 五、验收总口径（16 份 skill 冒烟，两层）

### 机器门禁断言（只考平台事实，不考模型行为）

1. **无假成功**：工具调用报成功 ⇒ 状态里真有对应变化（A1 分析落点、A2 描述字段逐一断言）；
2. **会喊疼**：白名单外参数 ⇒ 明确报错可见，不静默丢弃；
3. **事件卡**：每张卡在其触发时刻弹出（对 §四 批 2 表格逐卡断言），trace 有对应条目；规格更新复弹（V4-2）；
4. **无干扰**：状态尾无与 skill 矛盾的平台指令；UI 与状态尾无平台计算的"下一步"文案；
5. **不死锁**：脚本化全流程（含暂停→用户回复→续作）跑通到底；
6. **失败留痕与原子性**（V4-3）：失败报错含"保留状态 + 缺什么才能继续"；既有状态零污染（哈希比对）；
7. **能力缺口逃生口**（M4）：被 skill 声明为"平台待补齐/当前不可用"的步骤（如音乐 MV 第 6 步唇形同步），以"如实告知用户能力边界"为通过，不算卡死（flova3 末端"当前方案不支持直接接入音频素材"为同款姿势实证）。

### 判官观察层判据（拿 skill 原文对照聊天记录打分）

1. **首步正确**——按各自 skill 原文的尺子（商品宣传的首步是"写规格"，不是"剧本分析"）；
2. **四类停点规矩**——缺输入必问、高成本批次边界必停、决策点必问、花钱产物出后必等确认；低成本可逆产物（规格/故事板文字/元素图）不停，靠事件卡 + 随时打断。**16 份通用，不逐 skill 登记停点表**（V3-2）。**两层语义**（V4-1）：此判据在"确认型"偏好档下评估；档位语义 = 客观四类 × 用户偏好（`execution_preference`），不逐 skill 变化；
3. **A 类成熟剧本**（V3-5）——模型跳过分析并说明理由（转录同款："根据你提供的完整剧本，脚本确认阶段可以直接跳过"）；
4. **启动协议条件式**——缺项必问、不缺可跳且说明理由（不是无条件三问）；
5. **提示词草案独立确认**【V4-6 新增】——进入素材生成前，提示词草案先成文并留确认位（"草案已备好……尚未生成，请审阅"姿势）；对应偏好档为"素材生成前确认提示词"——我们的 `write_media_prompt` 工具已承载草案写入，观察模型是否正确使用这个中间态，**不建新机制**；
6. **流程外动作不被误伤**——生成海报/素材探索这类与 skill 流程无关的请求，照常执行（转录里 Flova 直接生成电影海报，无人拦）；
7. **能走到最后一步**——能力缺口按逃生口处理。

> 观察指标（只记录、不断言）：模型进入各阶段前是否调用 `read_skill` 取读对应章节（3333 全程未读）。判官层报告持续为零时再议是否立项。
