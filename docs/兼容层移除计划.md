# 兼容层移除计划

> 计划书 P1-8：为各兼容/废弃层定移除版本节点。**本文档只定计划，不执行删除**。
> 当前版本：v1.0.0（`web/app.py` FastAPI version 与 `package.json` 一致）。

移除节奏约定：每个版本节点执行前，先跑全量测试 + 手工冒烟；删除提交单独成 commit，
message 注明「移除兼容层：xxx（本计划 §N）」。

## 版本节点总览

| 兼容层 | 移除节点 | 前置条件 |
|---|---|---|
| `web/state_service.py`（DEPRECATED 壳） | **v1.1** | 无（已零引用） |
| legacy `studio.html` 回退 + `/legacy` + `/studio.html` 路由 | **v1.2** | dist 构建纳入启动流程 |
| 聊天端点别名 `/canvas-llm`、`/chat` | **v1.2** | §legacy 前端移除完成 |
| `state/models_legacy.py` 及其 re-export | **v1.3** | CLI 路径重构或确认弃用 |
| `StateManager._set_path_dict` 的 setattr 分支 | **v1.3** | 与 models_legacy 同步 |

---

## §1 `web/state_service.py`（v1.1）

**现状**：文件头自标 DEPRECATED，内容为 re-export 壳。经核查（2026-08），
`src/` 与 `tests/` 内已**零引用**。

**移除内容**：删除文件本身；`web/app.py` 的 import 与路由层早已迁到 `StateManager`，无需连带改动。

**验证**：`git grep state_service` 为 0；全量 pytest 通过。

## §2 legacy studio.html 回退（v1.2）

**现状**：三处 DEPRECATED 入口（均在 `web/app.py`）：

1. `_studio_page()`：`static/dist/index.html` 不存在时回退 `studio.html`；
2. `GET /legacy`：旧版对照入口；
3. `GET /studio.html`：旧 launcher iframe 的后缀兼容。

另有整套 legacy 资产：`static/studio.html`、`static/js/studio.js`、
`static/js/api-settings.js`、`static/api-settings.html`、`static/css/*`、`static/launcher.html`。

**前置条件**：
- `npm run build` 产物（`static/dist/`）纳入一键启动流程（`启动服务.bat` 增加构建检查），
  消除"dist 未构建"回退场景；
- 确认无外部 launcher 仍指向 `/studio.html`（`启动服务.bat` 已打开 `/`）。

**移除内容**：三个 DEPRECATED 路由改为 410/重定向到 `/`，随后删除 legacy 静态资产；
`static/` 仅保留 `dist/`、`images/`、`vendor/`。

**验证**：全量 pytest + vitest + Playwright 冒烟；手工确认 `/`、`/legacy`、`/studio.html` 行为符合预期。

## §3 聊天端点别名（v1.2，随 §2 之后）

**现状**：`web/routes/agent.py` 三个路径叠装饰器：

- 正名：`POST /api/agent/chat`、`POST /api/agent/chat/stream`
- 别名：`/api/canvas-llm`、`/api/chat`（及其 `/stream` 变体）

**依赖方**（2026-08 核查）：
- `static/js/studio.js`：两处调用 `/api/canvas-llm`（legacy 前端，§2 移除后消失）；
- `src/web/api/agent.ts`：一个兼容函数调用 `/api/canvas-llm`（删别名前改调 `/api/agent/chat`）。

**移除内容**：删掉别名装饰器，保留 `/api/agent/chat*` 唯一路径；同步修 `src/web/api/agent.ts`。

**验证**：`git grep canvas-llm` 仅剩 0 处；集成测试 `test_api_chat.py` 通过。

## §4 `state/models_legacy.py`（v1.3）

**现状**：`state/models.py` 顶部 re-export 一批 CLI 遗留模型
（`PlanStep` / `StoryboardState` / `Shot` 等），供 `cli.py` 工作流路径使用。

**前置条件**：二选一并先提方案给用户审核——
1. CLI 路径重构为现行 StateManager + Pydantic 模型体系；或
2. 确认 CLI 路径不再使用，直接下线 `cli.py`。

**移除内容**：`models_legacy.py` 文件 + `models.py` 的 re-export 块 + 依赖方适配。

## §5 `StateManager._set_path_dict` setattr 分支（v1.3，随 §4）

**现状**：`state/manager.py::_set_path_dict` 末尾对非 dict 对象走
`setattr(current, last, value)`，是 CLI Pydantic 对象路径的兼容分支；
Web 路径全部走 dict。

**移除内容**：§4 完成后该分支不再有调用方，删除并把 `_set_path_pydantic`
一并评估去留；`update()` 简化为纯 dict 路径 + 显式报错。

**验证**：状态相关单测（`test_state_*`、`test_undo_redo.py` 等）全绿。
