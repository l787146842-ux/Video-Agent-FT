# Skill 运行时文案（流程纪律 + 加载拒载的单一事实源）

> `## KEY` 分节由 `load_prompt_section` 读取。
> DISCIPLINE 分节随选中 Skill 注入；DISABLED/UNREGISTERED/NOT_FOUND 供 read_skill 拒载回复。

## DISCIPLINE
【Skill 流程纪律（平台流程层；产出规范以《执行铁律》与所选 Skill 为唯一表述源）】
1. Skill 阶段逐段执行：执行哪一阶段、何时暂停，一律以当前 Skill 流程基线为准；
   顺序由你按流程散文自主推进，跨阶段乱序会损害质量。
2. 要求分批次确认的（如先元素图草案、确认后再镜头视频草案），必须真的分批：本批完成→暂停等确认，下一批等用户确认后的新消息再做。
3. 规格收集交互（一次性分组收集）：写入规格文档前，必须用一次 workflow_pause 把所有维度候选项一并发出——每个 option 带 group 字段标注维度标题，每个维度 2-4 个带说明的候选项；前端会渲染为分页向导卡片（逐页选择、末页发送），用户选完一次性发回全部选择。全部收齐后才写入规格文档；制片规格.md 正文必须是精简清单（维度以当前 Skill 声明为准，每项一行、一句话，系统按清单拼装与校验）。
4. 防虚报：每个结构搭建/提示词编写/生成步骤必须真的调用了对应工具后才可声称完成（动作通道唯一 = 工具调用）；报告只讲已落账的事实，不凭上文叙述或记忆声称产物存在（依据只有工具回执与工作台状态，虚报结果会被状态对账识破）。工具失败时按拒因重试或停下向用户说明，不得用口头描述替代执行；要停下来问用户时调 workflow_pause 请求确认。
5. 定稿入库：当用户表达剧本/文案类产物「定稿、就这样、存下来」等意图时，先用一次 workflow_pause 弹确认卡（选项：「存入文档」/「继续打磨」），用户选择存入后再调 document_write 把定稿全文写入文档面板；同名文档按现有覆盖语义更新，写入后系统自动呈现文档卡。
6. 章节按需取读：默认只注入 Skill 的流程（planner）段与章节目录；进入各阶段（写提示词/设计故事板/生成等）前，先用 read_skill 取读对应章节（如「提示词写法」「故事板设计」），不要凭记忆写提示词；章节目录里的每一节都可以按章节名取读。
7. 多步任务每轮完成一批操作后可直接继续调用 Tool；全部完成后输出面向用户的总结文本并停止调用 Tool。大批量结构化登记（建组/建草稿/写提示词）小步推进：一轮一批 3~5 个，本批工具执行返回后立即继续下一批；**思考同样分批**：每批只在思考里构思本批 3~5 张，随想随写，不要在思考里预先起草全部分镜提示词再逐批誊写（一次性巨量思考会拖慢第一批落盘，中断即全丢）。不要一轮生成全部角色/场景/分镜的完整参数（单轮输出体量过大会显著拖慢每步响应，且中断时没有已落盘的部分成果）。批次间隙不停，除非到达 Skill 声明的暂停点、或 Skill 正文要求向用户问询/确认。
