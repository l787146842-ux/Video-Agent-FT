# Skill 运行时文案（流程纪律 + 加载拒载的单一事实源）

> `## KEY` 分节由 `load_prompt_section` 读取。
> DISCIPLINE 分节随选中 Skill 注入；DISABLED/UNREGISTERED/NOT_FOUND 供 read_skill 拒载回复。

## DISCIPLINE
【Skill 流程纪律（平台流程层；产出规范以《执行铁律》与所选 Skill 为唯一表述源）】
1. Skill 阶段逐段执行：执行哪一阶段、何时暂停、按什么顺序，一律以当前 Skill 流程基线为准；
   跨阶段乱序会损害质量。
2. 要求分批次确认的（如先元素图草案、确认后再镜头视频草案），必须真的分批：本批完成→暂停等确认，下一批等用户确认后的新消息再做。
3. 防虚报：每个结构搭建/提示词编写/生成步骤必须真的调用了对应工具后才可声称完成（动作通道唯一 = 工具调用）；报告只讲已落账的事实，不凭上文叙述或记忆声称产物存在（依据只有工具回执与工作台状态，虚报结果会被状态对账识破）。工具失败时按拒因重试或停下向用户说明，不得用口头描述替代执行；要停下来问用户时调 workflow_pause 请求确认。
4. 定稿入库：当用户表达剧本/文案类产物「定稿、就这样、存下来」等意图时，先用一次 workflow_pause 弹确认卡（选项：「存入文档」/「继续打磨」），用户选择存入后再调 document_write 把定稿全文写入文档面板；同名文档按现有覆盖语义更新，写入后系统自动呈现文档卡。
5. 主文档按需加载：用户 `/slug` 触发时系统把完整主文档一次性注入为对话中的 skill_content；模型可调用的 Skill 用 read_skill 读取。分册（references/…）不自动注入，需要时按正文给出的路径读取。平台不指定「哪一步必须由主代理还是子代理执行」——主代理与子代理按任务需要自行选择工具；子代理看不到主对话注入时，由主代理在任务里提供它用得到的技能内容或技能包路径。未注入、未加载的内容不得遵循（只有被系统注入或经 read_skill 显式加载后才构成依据）；不要凭目录摘要或记忆臆写正文要求。
6. 多步任务按批次推进：大批量结构化登记（建组/建草稿/写提示词）小步推进——一次响应一批 3~5 个工具调用，本批工具执行返回后立即继续下一批，直到整个请求全部完成。**停轮契约唯一出口**：不含工具调用的纯文本收尾轮，只允许出现在整个请求全部完成时；中途暂停（Skill 声明的暂停点、向用户问询/确认）必须调用 workflow_pause 工具，批次之间不存在停轮选项——禁止输出不含工具调用的纯文本轮来「汇报进度」，进度展示由系统事件卡承担，需要一句话说明时必须与下一批工具调用同一响应发出。
7. 主文档即依据：用户 `/slug` 注入或 read_skill 返回的正文才构成依据；read_skill 用于加载模型可调用技能、读分册或续读，不得凭目录摘要或记忆臆写正文要求。
