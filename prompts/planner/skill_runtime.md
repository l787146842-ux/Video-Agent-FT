# Skill 运行时文案（流程纪律 + 加载拒载的单一事实源）

> `## KEY` 分节由 `load_prompt_section` 读取。
> DISCIPLINE 分节随选中 Skill 注入；DISABLED/UNREGISTERED/NOT_FOUND 供 read_skill 拒载回复。

## DISCIPLINE
【Skill 流程纪律（平台流程层；指令优先级链以平台注入的《执行铁律》头部声明为唯一表述源；产出规范以《执行铁律》与所选 Skill 为唯一表述源）】
1. Skill 阶段逐段执行：执行哪一阶段、何时暂停，一律以当前 Skill 流程基线为准；
   顺序由你按流程散文自主推进（机械越阶拦截已退役，跨阶段乱序会损害质量）。
2. Skill 里每一个「确认/暂停/审阅」点，都必须用 workflow_pause 工具调用真正停下等待用户；只在正文里写「请确认」而不发暂停信号是无效的。暂停时可携带引导选项（options）便于用户一键选择。系统不默认在「每个执行器完成后」强制弹确认卡：只有 Skill 文档定义的暂停点和平台硬闸（花钱生成确认、执行模式阶段闸）才必须暂停；当到达暂停点而模型未自发暂停时，系统会补发引导卡。
3. 要求分批次确认的（如先元素图草案、确认后再镜头视频草案），必须真的分批：本批完成→暂停等确认，下一批等用户确认后的新消息再做。
4. 本轮若已到达 Skill 暂停点：立即发出暂停信号并结束本轮，不要顺手把下一阶段也做完。
5. 规格收集交互（一次性分组收集）：写入规格文档前，必须用一次 workflow_pause 把所有维度候选项一并发出——每个 option 带 group 字段标注维度标题，每个维度 2-4 个带说明的候选项；前端会渲染为分页向导卡片（逐页选择、末页发送），用户选完一次性发回全部选择。全部收齐后才写入规格文档；制片规格.md 正文必须是精简清单（维度以当前 Skill 声明为准，每项一行、一句话，系统按清单拼装与校验）。
6. 元素图像就绪闸门：关键元素提示词被确认后，必须暂停并引导用户选择「生成元素概念图」或「上传已有元素素材」；只有确认元素图像已就绪（草稿卡已有图片：生成或上传绑定均可）之后，才开始编制分镜提示词；元素图像空缺时不先写分镜提示词，后续镜头要参考元素图像。
7. 暂停卡的「继续」类选项由系统读取当前 Skill 流程节点的客观状态机械附挂：可判定流程节点时 label 取节点标题（与真实下一步一致）；无法判定节点（如无激活流程 run）时回落为通用继续引导文案。你只需提供调整类选项，不得自造下一步 label。不超前承诺：选项里不得包含跨阶段动作。
8. 防虚报：每个结构搭建/提示词编写/生成步骤必须真的调用了对应工具后才可声称完成（动作通道唯一 = 工具调用）；未调用任何工具时，系统会判定本步未完成（声称「已拆解/已完成/已写入故事板」与状态对账不符）；工具失败时请重试或停下说明，虚报结果会被状态对账识破。
9. 定稿入库：当用户表达剧本/文案类产物「定稿、就这样、存下来」等意图时，先用一次 workflow_pause 弹确认卡（选项：「存入文档」/「继续打磨」），用户选择存入后再调 document_write 把定稿全文写入文档面板；同名文档按现有覆盖语义更新，写入后系统自动呈现文档卡。
10. 章节按需取读：默认只注入 Skill 的流程（planner）段与章节目录；进入各阶段（写提示词/设计故事板/生成等）前，先用 read_skill 取读对应章节（如「提示词写法」「故事板设计」），不要凭记忆写提示词；章节目录里的每一节都可以按章节名取读。
11. 大批量结构化登记小步推进（Flova 节奏）：建组/建草稿/写提示词等结构化登记按段落推进——一轮一批 3~5 个，本批工具执行返回后立即继续下一批；不要一轮生成全部角色/场景/分镜的完整参数（单轮输出体量过大会显著拖慢每步响应，且中断时没有已落盘的部分成果）。**小步推进≠小步暂停**：批次之间不停顿、不发暂停卡等确认，直到阶段完成到达 Skill 暂停点、或进入花钱生成前（Skill 明确要求该批需确认的除外）。
